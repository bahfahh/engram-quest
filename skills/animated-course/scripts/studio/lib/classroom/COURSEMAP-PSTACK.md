# 課程地圖：pstack 拆解課 `coursemap-pstack.js`

> 三課 pstack 課（ps-l01-shape、ps-l02-trust、ps-l03-fit）共用的課程地圖。API 形狀照 `coursemap4.js`（`times`、`cam(t)`、`applyCam`、`update(t, cam)`、`shot`），呼叫方式一樣。
> 依照 `reference/04-skeleton.md` §5 做的：要看的零件停 2～3 秒以上；全景時整張桌子（三個零件）都在畫面裡；看某一課就推到那個零件、其他變淡，沒有停在半近半遠的鏡頭；一次只亮一組；名牌和看板在當下鏡頭距離 ≥ 28px（全景時看板約 30～40px、名牌約 45px；推近後看板 70px 以上，工作單上的字約 35px）。
> 測試頁：`projects/zz-map-test/scene.html`（同一條時間軸上放了五種用法，時間跟三課的 timeline 對齊）。

## 桌上有什麼

三個黏土零件左到右排（第 1、2、3 課），各是那一課核心機制的小模型，每個都會真的演一遍：

| 課 | 名牌 | 演什麼（一輪，速度 1） | 顏色 |
|---|---|---|---|
| 1 | 劇本軌道 | 工作單（「目標／完成檢查 ☐」）穿過深藍入口 `/poteto-mode` → 入口的箭頭轉向，三條軌道裡中間那條亮橘色（看板「劇本 Bug fix」變亮）→ 卡片往前走，軌道後面 1～6 格一格一格亮 → 走到綠色壓印機，蓋下綠色「證據」章、☐ 變 ✓、地上亮一圈綠光。**3.6 s** | 入口深藍 #1C2340、劇本橘 #F2780C、證據綠 #2EA44F |
| 2 | 三道關 | 一份「報告」卡在輸送帶上過**三根柱子**（三道門）：①「貼標籤」：卡片上依序冒出 量到（綠）／推論（藍）／猜（灰）三個標籤；②「另一家重跑」：後面升起兩張卡，「說法」被打 ✗、從後緣掉下去消失；「▶ 重跑」翻成紅色 FAIL、加綠框（留下）；③「擋板」：留下的 FAIL 卡飛過去，變成一塊立在門邊的紅色 ✗ 擋板 → 報告通過 → 線分岔成四條變綠的平行線，四張 ✓ 卡跑出去；出口是一個平躺的綠色箭頭牌「放行 →」（不是第四根柱子）。**4.4 s** | 說法灰 #A3A7B0、FAIL／擋板紅 #E5484D、通過綠 |
| 3 | 兩條流水線 | 上游紫色平台（看板「SDD｜人拍板」）：「?」卡送到一個人面前，他拍板，卡變成「✓ 拍板」→ 送進 decision table（全景時表頭寫「決策表」），第二列「送兩次 → 只算一次」填上並亮紫色 → 那一列複製一份，順著地上的紫→藍箭頭滑到下游藍色輸送帶（看板「pstack｜跑得出答案」），變成「完成檢查 ☐」卡 → 進「▶ 跑」箱，出來變 ✓ → 盡頭一個藍色插頭插進木塊「插上 plugin」，木塊亮綠（第 3 課的「怎麼裝」）。**4.6 s** | 人才能答紫 #7C5CD6、跑得出答案藍 #2B8FD6、完成檢查綠框 |

**小字只在推近時出現**：零件上的小字（卡片內容、三個標籤、說法／FAIL 卡、decision table 的列、完成檢查、步驟格的數字、「▶ 跑」）在全景時畫成灰色字條（看得出「有字」但不硬塞讀不到的字），鏡頭推到那個零件時才換成真的字（推近時 ≥ 28px）。全景只留讀得到的大標：名牌、`/poteto-mode`、劇本 Bug fix、交證據、三根柱子的牌、放行、SDD｜人拍板、決策表、pstack｜跑得出答案、插上 plugin。切換點是「全景到推近距離的一半」，自動判斷，不用設定。

同一個零件的三種狀態：**亮**（有顏色、正在演、名牌變黃、底下一圈淡黃光）／**學過的**（有顏色，停在演完的樣子）／**還沒學或其他零件正在亮時**（變淡：去飽和、往桌面的淡色靠，輪廓還看得出來）。

全課收尾（`shot: 'chain'`）：第 3 課的零件從後面繞到最左邊，1、2 往右挪，中間接上兩段藍色連接帶，排成一條：**SDD 拍板 → decision table 一列 → 完成檢查 → 入口挑劇本 → 交證據 → 三道關 → 平行**（跟 ps-l03-fit 結尾心智圖的順序一樣），再讓東西從頭跑到尾一次，每到一段就亮那一段，最後三段一起亮。

## 1. 用法

```js
import { makeCourseMapPstack } from '/lib/classroom/coursemap-pstack.js';   // 也可以 import { makeCourseMap } 或 default
const map = await makeCourseMapPstack({ lesson: 2, t0: Ls('O07'), question: '憑什麼敢放手讓它跑？', camFrom: CAMS.W, camBlend: 1.0,
  times: { parts: [Wd('O07', '第一課')], arrive: Ls('O08') + 0.5, colorIn: Ls('O08'), ask: Ls('mapbeat'), end: Le('mapbeat') } });
scene.add(map.root);

window.renderAt = (t) => {
  const onMap = t >= map.times.start && t < map.times.end;
  map.root.visible = onMap;
  if (onMap) { map.applyCam(cam, t); map.update(t, cam); }    // update 放在設好鏡頭之後（名牌和問題卡要轉向鏡頭）
  else { /* 你自己的鏡頭 */ }
  renderer.render(scene, cam);
};
```
匯出：`makeCourseMapPstack`（主要）、`makeCourseMap`（同一個函數的別名）、`default`（同上）、`COL`（顏色意義表）、`PARTS_PSTACK`（三個名牌名）。

`update(t, cam)`、`cam(t)`、`applyCam(cam, t)` 都是 **t 的純函數**（任何順序、任何時間，同一格畫面一樣）。頁面記得 `RENDER_GPU=1`。字型：元件自己會載入 Chiron GoRound TC 700 和 Inter 800。

### 參數 `makeCourseMapPstack(o)`

| 參數 | 預設 | 說明 |
|---|---|---|
| `lesson` | 必填 | 這一課，1～3 |
| `t0` | `0` | 地圖段開始的秒數 |
| `shot` | `'ride'` | `'ride'` 開場（全景 → 依序亮 → 推到這課的零件 + 問題卡）／`'chain'` 全課收尾，三個零件接成一條／`'finale'` 從這課零件的近景拉回全景／`'overview'` 停在全景。`shot: 'overview', allLit: true` 用在 `lesson: 3` 時就等於 `'chain'`（跟 coursemap4 第 13 課的 lap 一樣） |
| `question` | `''` | 問題卡的字（`ride` 才有）。一行約 12 個中文字以內，要兩行用 `'\n'`。卡上方自動加「第 N 課 · 名牌名」 |
| `times` | 自動 | 跟旁白對時間用，**絕對秒數**，見 §3 |
| `stops` | 第 1 課 `[1,2,3]`；第 2 課 `[1]`；第 3 課 `[1,2]` | `ride` 推近之前，在全景裡依序亮的零件（第 1 課＝三個都演一次；後面的課＝學過的快速複習） |
| `review` | `'wide'` | `'wide'`：複習和第一次看全貌都在全景裡亮（整桌都在畫面裡）。`'push'`：鏡頭推到每個 stop 去看（比較慢，每個 stop 至少給 3 s） |
| `camFrom` | 無 | `{pos, look, fov}`（世界座標 `THREE.Vector3`）：從你的鏡頭在 `t0` 開始平滑接進地圖鏡頭 |
| `camBlend` | `1.2` | 這段接進來要幾秒 |
| `allLit` | `false` | `overview` 時三個都亮（lesson 3 時變成 `chain`） |
| `place` | `{x:0.1, y:0, z:-0.55, rotY:0, scale:1}` | 地圖桌放哪（預設就在矮桌的位置；用地圖時不要再放 `C.makeLowTable()`） |
| `table` | `true` | `false`：不要展示桌，零件板直接放在 `place.y` |
| `parts` | `{}` | 改零件上的字：`{1: {name, entry, playbook, evidence, goal, done}, 2: {name, gate1, gate2, gate3, report, tags, claim, parallel（出口箭頭的字，預設「放行」）}, 3: {name, upstream, downstream:[l1,l2], rows:[3 列], table, tableShort（全景表頭，預設「決策表」）, doneLabel, plugin:[l1,l2]}}`。預設字已對過 SERIES 名詞表，非必要不要改 |

### 回傳

| 名稱 | 說明 |
|---|---|
| `root` | 加到 scene 的 Group |
| `update(t, cam)` | 擺好第 t 秒的所有東西 |
| `cam(t)` / `applyCam(cam, t)` | 地圖鏡頭（世界座標 `{pos, look, fov}`）／直接套到 `PerspectiveCamera` |
| `times` | `{ start, overview, stops:[{n, t, end, rate}], push, arrive, colorIn, ask, end, lit:[{n,t}] }`（`ride`）；`{ start, join:[a,b], flow:[f3,f1,f2], rate?, end, lit }`（`chain`）。`console.log(JSON.stringify(map.times))` 看實際數字 |
| `cams.overview()`、`cams.part(n)`、`cams.chain()` | 固定鏡頭：全景／零件 n 的近景（這課的零件會包含問題卡）／接成一條後的全景 |
| `partWorld(n)` | 零件 n 在桌上的世界座標（要包老師指它、加特效時用） |
| `itemWorld(n)` | 零件 n 正在動的那張卡（工作單／報告／完成檢查）的世界座標，取最近一次 `update` 的位置。第 1 課要「從工作單推近，交接到終端機」時用它當鏡頭目標 |
| `parts`、`land` | 內部物件（一般不用碰） |

## 2. 三種用法怎麼呼叫（建議值，跟目前三課的 timeline 對過）

### 第 1 課：第一次看全貌（三個零件依序各演一次，再停在第 1 個 + 問題卡）

  times: { parts: [Ls('O09b'), Ls('O09c'), Ls('O09d')], arrive: Ls('mapbeat') + 0.2, colorIn: Ls('mapbeat') - 0.3, rate: 1.4, end: Ls('A01') } })

| 零件 1 亮 | 59.43–63.47 | 4.0 s（以 1.0× 演完一輪） | 全景，只有零件 1 有顏色 |

### 其他
- `shot: 'finale'`：從這課零件的近景拉回全景，預設 4 s，零件持續循環演。
- `shot: 'overview'`：全景不動，`n ≤ lesson` 的零件有顏色並循環演（每輪中間停 2.2 s），其他淡著。

## 3. 對時間（`times`，全部是絕對秒數）

`ride`：
| 鍵 | 預設 | 說明 |
|---|---|---|
| `overview` | `t0` | 全景開始（通常就是 `t0`） |
| `parts`（或 `stops`） | 自動排 | 每個 stop 亮起的秒數，跟 `stops` 一一對應。給了 `arrive` 沒給 `parts`：平均排在「全景停完」和「開始推近」之間 |
| `arrive` | 最後一個 stop + 3.0 s（第 1 課）/ 2.9 s + 1.1 s | 鏡頭推到這課零件停好的秒數；問題卡預設這時出現 |
| `push` | `arrive − 1.1` | 開始推近的秒數；最後一個 stop 亮到這裡 |
| `colorIn`（或 `play`） | 第 1 課 `push + 0.15`；其他 `arrive − 0.6` | 這課零件上色、從頭開演 |
| `rate` | `1` | 這課零件演的速度（1.4 ＝ 3.6 s 的一輪用 2.6 s 演完） |
| `ask` | `arrive` | 問題卡跳出來 |
| `end` | `max(ask + 2.6, colorIn + 一輪 + 0.4)` | 地圖段結束；鏡頭在 `end − 0.5` 之後不再動（方便拿最後一格當 DOM 頁的貼圖） |

- 每個 stop 從亮起到下一個 stop（或 `push`）就是它的視窗。演的速度自動算：`rate = clamp(一輪 / (視窗 − 0.5), 1, 1.8)`，所以視窗夠長就以 1× 演完再停在演完的樣子；視窗短就最多加速到 1.8×。**每個 stop 的視窗請給 ≥ 2.5 s**（低於 2.5 s 時零件 2、3 會演不完就變淡）。
- 學過的零件在自己的 stop 之前停在「演完的樣子」，亮起時從頭演；沒學過的停在起始樣子。

`chain`：
| 鍵 | 預設 | 說明 |
|---|---|---|
| `join` | `t0 + 0.5 + camBlend × 0.5` | 開始換位置（1.6 s 換完） |
| `flow` | 自動 | `[零件 3 開演, 零件 1 開演, 零件 2 開演]`；每段的速度由到下一段的間隔自動算（1～2.2×） |
| `end` | 最後一段演完 + 1.6 s | 結束；只給 `end` 不給 `flow` 時，三段平均壓進可用時間 |

## 4. 每個零件停幾秒（速查）

| 情況 | 停多久 |
|---|---|
| 全景（第一次看全貌） | 建議 ≥ 2.5 s（第 1 課實際 3.7 s） |
| 全景（第 2、3 課） | 建議 ≥ 1.5 s；複習本身也在全景裡，整桌在畫面裡的總時間會再加上複習的秒數 |
| 一個零件亮（第一次 / 複習） | ≥ 2.5 s；完整演一輪在 1× 時：零件 1 3.6 s、零件 2 4.4 s、零件 3 4.6 s |
| 推近 | 1.1 s |
| 問題卡 | ≥ 2.0 s（11 字的卡約要 2 s 讀完；第 1 課建議 2.8 s） |
| 收尾接成一條 | 換位置 1.6 s ＋ 每段 ≥ 4 s ＋ 全部亮著停 ≥ 3 s；整段 ≥ 16 s |

## 5. 交接與鏡頭

- 從教室接進來：`camFrom` + `camBlend`（建議 1.0 s）。接回你的鏡頭：在 `times.end` 之後自己 lerp（同 COURSEMAP4 §4）。
- 交接到 DOM 頁：鏡頭在 `end − 0.5` 停住；最後一格拿 `RENDER_GPU=1 node render.cjs <project> --scene classroom.html --stills <end>` 出圖當貼圖。
- 推近時，這課零件的名牌會讓位給問題卡（跟 coursemap4 一樣）。推近鏡頭的下緣留給字幕（底部 140px 沒有東西）。
- 推近到工作單（第 1 課）：`const p = map.itemWorld(1)` 拿到卡片位置，從 `map.cam(t)` lerp 到對著 `p` 的近鏡頭。

## 6. 算圖成本

1920×1080、SwiftShader、教室＋地圖：每格約 3～4 s（全景與近景差不多），第一格再加約 5 s（字型、canvas 貼圖、shader）。地圖不在畫面上時設 `map.root.visible = false`。

## 7. 已知限制

- 第 1 課的三條軌道裡，後面那條（`z = −0.17`）大部分被步驟格擋住，只看得到中間（被挑中的、橘色）和前面那條（灰）。表達的是「挑其中一條」，沒有畫出 23 條。
- 全景鏡頭是寬度決定的（三個零件橫排），所以畫面下方會有一段桌面。全景時小字是字條（見上），要推近才讀得到；全景要讀的是看板和名牌（大多 ≥ 28px；「插上 plugin」「放行」約 24px）。
- 名牌只繞垂直軸轉向鏡頭。
- 沒有音效：要的話在 `times.ask`（問題卡）和各 stop 的亮起時間加一個小「pop」。
- API 只會長大：已公開的參數和回傳不改。
