# 09 重用與加速


## 1. 時間花在哪（第三輪第一階段）

| 事 | 每支片 | 能不能重用 |
|---|---|---|
| 讀 skill、讀筆記、寫 CONTENT | 約 20 分鐘 | 主題內容可以快取（第 3 節） |
| 建外殼（房子、鐵軌、牆、光） | 約 20～30 分鐘 | **可以**：外殼做成元件，只換參數 |
| 做演示（分數條、連線池、並排比……） | 約 20 分鐘 | **可以**：常見演示做成元件 |
| 自己寫工具（閱讀檢查、定格、cue sheet、混音） | 約 10 分鐘 | **已經統一**（`07-製作與工具.md` 3.5 節） |
| 檢驗、修改 | 一到兩輪 | 交件前先用同一套工具自查，少一輪 |
| 全片算圖 | 本機 5 小時以上 | **雲端分段平行算**（`templates/雲端算圖session.md`） |

## 2. 每輪做完要收回 skill 的東西

**第三輪已收回：**
- **外殼**：`assets/shells/rooms|rewind|board/` 換成第三輪三支片的生產程式（雲端算圖實際用的那一份，逐位元組沒改），各附 README（換內容的地方、旋鈕、坑、不要改什麼）。
- **演示元件**：`assets/demos/`，三份目錄共約 46 個演示（ep-sep 14、ep-aug 19、ep-oct 13），附 50 多張定格、程式位置、參數、成片時間；`assets/demos/README.md` 依「演什麼」找。
- 工具：`assets/tools/clarity-ep-oct.cjs`（讀得到檢查）、各外殼裡的 `check_reading.mjs`。

**還沒做（下一輪的整理項目）：**
1. 外殼**集中成一個設定**（站數、案件數、房間數、季節和時段、光）：目前寫死在各檔，換數量要改好幾處。重構前要先有定格比對，確認外觀沒變。
2. 演示裡寫死的數字（Rubric 的 15／19、連線池的 ≈205）改成從 `content.js` 讀。
3. 讀得到檢查改成讀 `film.json`（現在三份各自寫）。
4. `rewind/assets/*.svg` 的中文字先轉成 PNG（雲端算圖機沒有 CJK 字型會缺字）。
5. 有新的、通過檢驗的演示就補進 `assets/demos/`，每個附一張定格和參數說明；新的錯寫進 `08-經驗與避坑.md`。

## 3. 主題內容快取（之後做）

- 每個主題的 `CONTENT`（10 項）和 `DEMO`（每個概念的演示）存在 vault 的 `engram-quest/episodic-review/topics/<主題>/`。
- 下個月同一個主題又被動到：只讀這個月改過的筆記，看結論有沒有變；沒變就沿用，只更新情境那一行。
- 收集程式（`collect.py`）比對快取，標出「新主題／有改／沒改」。

## 4. 放進插件（給開發者的建議，使用者決定）

讓裝了 engram-quest 的人不用從頭準備：
- **外殼和演示元件**、**配樂取樣和產生器**、**算圖工具**放進插件的資源，skill 只指向插件的路徑；這樣不需要網路，也不用每次 `npm install`。
- 插件提供「這個月的回顧」入口：跑 `collect.py`、列出主題、讓使用者勾要走進去的主題，再交給 AI 照這個 skill 做。
- 影片庫已經有 `episodic-recall/` 和 `meta.json`；可以加「主題」欄位，讓使用者只重看某一個主題段（主題段的起訖秒數由 `film.json` 匯出成章節）。
