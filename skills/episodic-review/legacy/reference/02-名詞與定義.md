# 02 名詞與定義

> 只放名詞和定義；為什麼這樣定，看 `01-基本觀念.md`。
> 規則：**一個名詞在整個流程只有一個意思**。筆記、script、主題內容檔、分鏡、片子都用同一套。
> 「程式用名」是之後 script、檔案欄位用的英文名。
> 最後更新：2026-11-01

## 0. 「房間」改叫「主題」

「房間」只適合一種風格，所以通稱改成**主題**；房間、案件、站是各風格裡的樣子。

| 用在哪 | 名詞 |
|---|---|
| 內容、流程、script、檔案 | **主題** |
| 片子裡呈現一個主題的那一段 | 主題段 |
| 「回到那個房間」風格裡 | 房間 |
| 「線索板」風格裡 | 案件 |
| 「倒帶」風格裡 | 站 |
| 「思考城堡」風格裡 | 一座結構 |

為什麼用「主題」：
- **跟風格無關**。換風格不用換名詞，只換外殼。
- **陌生人一看就懂**，不用先解釋比喻。
- **流程裡本來就叫主題**：`collect.py` 輸出的 `topics/`、主題頁都是。從頭到尾一個詞，skill 不用來回翻譯。
- 注意：這裡的「主題」只指內容（topic），不指外觀。外觀一律叫「風格」。

沒選的詞：

| 詞 | 為什麼不用 |
|---|---|
| 房間 | 只適合一種風格 |
| 場景 | 跟「場景記憶」撞名，也容易被當成一個鏡頭 |
| 記憶點 | 日記裡已經拿來記當天的事 |
| 單元 | 像課程，但這不是教學片 |
| 節點 | 跟 canvas 上的卡片撞名 |
| 錨點 | 意思是線索，只講到入口，沒講到內容 |
| 章 | 可以當第二選擇（播放器可以把每個主題段標成章節），但「章」強調先後，主題之間其實是並列、互相連結 |

## 1. 目的和標準

| 名詞 | 程式用名 | 定義 | 例子、不是什麼 |
|---|---|---|---|
| 情境回顧 | `episodic-review` | 把一段期間學過的主題整理成片，讓人想起當時為什麼學、怎麼想、結論是什麼、後來有沒有修正，拿回來用 | 不是教學片（沒有老師和教室、不從零教、不加筆記以外的資料）；但要照筆記的深度解釋概念、做法和案例。不是活動紀錄 |
| 回顧片 | `film` | 一段期間做一支片，現在定一個月一支 | |
| 陌生人檢驗 | `stranger-test` | 把主題內容給沒看過這些筆記的人（或沒讀過的 AI），請對方用自己的話講回：這主題在回答什麼、結論、為什麼。講得出來才算過 | 回顧片的驗收標準之一；另一半是畫面的檢驗（第 6 節） |
| 內容為王 | | 先決定內容（主題和它的道理），情境最後才加；沒寫日記也不影響內容 | |

## 2. 內容

| 名詞 | 程式用名 | 定義 | 例子、不是什麼 |
|---|---|---|---|
| 筆記 | `note` | vault 裡的一篇 `.md`，是一個完整的想法：整篇讀，不切成段落或句子 | |
| 最終現況 | `current` | 筆記現在的樣子。內容只看這個 | 中間的改動、哪天幾點存的都不看 |
| 主題 | `topic` | 講同一件事的一組筆記，是回顧的單位。期間內只動了一篇，也要拿整組 | Auth：dotnet-auth 地圖 01～04，加上連回來的 SampleApp〈05_auth_rbac〉 |
| 領域 | `domain` | 主題的上一層分類，用使用者自己的資料夾 | 12.軟體工程、11.ai-coding；全貌依領域分組 |
| 結構 | `structure` | 使用者自己整理好的關係：資料夾、地圖系列、canvas、筆記之間的連結。AI 直接用，不重新拆解，也不另外發明關聯 | |
| 地圖系列 | `map-series` | 「…地圖」資料夾裡編號 01～0N 的筆記，編號順序就是使用者安排的閱讀路線 | dotnet-auth 地圖 01→04 |
| canvas | `canvas` | Obsidian 的白板檔：卡片、群組、箭頭、連線上的字。一律先畫成圖再看 | 只讀 JSON 容易看錯 |
| 雙向連結 | `links`、`backlinks` | 這篇連出去的，和別篇連回來的（反向連結），兩邊都要看 | |
| 內容形狀 | `shape` | 主題的邏輯長怎樣：分類／全景、比較／互相牽連、結論有來由／前後修正。用來選風格 | |
| 顆粒度 | `depth` | 筆記把一個主題寫到多細，分四層：L1 名稱（有哪些）、L2 概念（是什麼、防誰、為什麼）、L3 做法（步驟、指令、規則寫法、範例程式、清單）、L4 案例（用在真實的案子上、事故、報告）。**片子講到筆記最深的那一層**，筆記沒寫的不補 | 品質防線：筆記寫到 L3～L4（必跑指令、mutation 報告、採購系統的風險清單），第一版的片只到 L1～L2。見 `03-內容.md`、`04-演示.md` |
| 主線案子 | `case` | 從筆記裡挑一個具體的案子（專案、事故、一條規則），讓它走過整個主題的結構，概念跟著它出現 | 品質防線用「採購預測系統」和「明細加總＝單頭總額」這條規則 |
| 圖 | `figures` | 主題現成的圖：筆記嵌的 SVG／PNG、mermaid、canvas 畫成的圖、複習卡裡的圖解。先用現成的，沒有才照筆記內容畫 | 〈AI-coding品質防線光譜.svg〉〈qcard-mutant案例.svg〉 |

## 3. 一個主題的內容

每個主題寫這 10 項（主題內容檔裡一個主題一段）。2～4 項要照筆記的顆粒度寫：筆記寫到做法和案例，這裡就要有。

| 名詞 | 程式用名 | 定義 | 例子、不是什麼 |
|---|---|---|---|
| 問題 | `question` | 這個主題在回答什麼，白話一句 | 「幫一個 app 做登入，到底要決定什麼？」 |
| 重點 | `points` | 照筆記自己的結構排的 3～5 點，每點一兩句白話；術語第一次出現時用一句話說明 | 不是一篇筆記一行的清單 |
| 做法 | `howto` | 筆記寫的「實際怎麼做」：要跑什麼、規則怎麼寫、失敗時看到什麼。程式碼挑最短最能說明的 3～6 行，配一句白話 | 「每次改完必跑：`dotnet build`、架構測試、`eslint --max-warnings 0`」 |
| 案例 | `example` | 主線案子在這個主題裡長什麼樣、擋下了什麼 | 採購系統：「人工改過的數字被同步蓋掉」→ 每種人工值各一個「重新同步後值不變」的測試 |
| 圖 | `figures` | 這個主題要放的圖和圖型（流程、分層、心智圖、對照表、截圖），附路徑 | 程式碼的一生：四關流程圖；同一句規則講三次：分層圖 |
| 判斷規則 | `rule` | 筆記裡寫的「怎麼選」「什麼時候用」，最好有一句一針見血的 | 「外部登入選哪家：跟著資料庫走」 |
| 修正 | `revision` | 筆記裡自己寫的前後判斷不同。筆記沒寫就沒有 | 「當年不選 OAuth 的理由，要重新評估」；不是比對改動紀錄得來的 |
| 先問後給 | `recall` | 1～2 題：問道理，等你想，再給答案（答案用筆記內容） | 不問日期、檔名 |
| 未解問題 | `open` | 筆記裡寫了、但還沒定的事 | 不是「canvas 哪張卡沒更新」這類整理工作 |
| 情境 | `context` | 一行，給本人的入口：那時在做什麼、看了什麼 | 「8 月底，對照之前 SampleApp 專案的做法」 |
| 出處 | `sources` | 用到的筆記標題。片中只在揭曉時用小字放標題，不放路徑 | |

整段期間另外有：

| 名詞 | 程式用名 | 定義 |
|---|---|---|
| 全貌 | `overview` | 期間內動過的全部主題，依領域分組，每個一句「它在回答什麼」，加上主題之間怎麼接 |
| 快問 | `quick-quiz` | 片尾 2～3 題，拿掉外殼、情境、時間再問一次 |

## 4. 時間

| 名詞 | 程式用名 | 定義 | 例子、不是什麼 |
|---|---|---|---|
| 期間 | `period` | 一支片涵蓋的時間，現在是一個月 | |
| 動過 | `touched` | 期間內建立或改了內容的筆記。只用來選出要回顧的主題 | 不是內容，也不決定內容順序 |
| 學習日 | `learn-day` | 台灣時間，凌晨 5 點前算前一天。只在判斷「動過」時用 | |
| 整庫重整 | `bulk-day` | 一次大量搬移或改名的日子，當例外處理：那天的搬移不算動過 | 9/4、10/27 |
| 情境裡的時間 | | 只寫到「8 月底」「9/4 那天」這種程度 | 不寫幾點幾分 |

## 5. 記憶（設計依據，細節見`01-基本觀念.md` 第 7 節）

| 名詞 | 定義 | 在片子裡變成什麼 |
|---|---|---|
| 情境記憶 | 使用者的用語，指情境依賴記憶：用學習當時的情境（問題、專案、來源）當線索，把知識叫回來 | 每個主題一行情境。學術上的「情節記憶」是自己經歷過的事；這裡情境只當入口，主體是道理 |
| 熟悉感 | 覺得「有寫過」，但講不出內容 | 日期、檔名只給熟悉感，所以不拿來當內容 |
| 提取練習 | 自己想出來，比再看一次記得牢 | 先問後給 |
| 多情境提取 | 換掉情境再想一次，才不會只在原本的情境想得起來 | 快問 |
| 分塊、基模 | 有結構的東西好記 | 用主題原本的結構呈現，不打散 |

## 6. 片子

| 名詞 | 程式用名 | 定義 | 例子、不是什麼 |
|---|---|---|---|
| 風格 | `style` | 片子的外觀。現有四種：回到那個房間、倒帶、線索板、思考城堡；也可以都不選、自己設計更好的。**先讀懂內容才選**，不硬套；一支片可以混用 | 舊稱「展示方式」。見 `05-風格.md` |
| 外殼 | `shell` | 風格裡的比喻空間（房子、牆、軌道）。外殼服務內容；比喻抓意思，不照字面蓋。**認可過的外殼照用**，只換內容，不重新設計 | 第一輪「思考城堡」蓋了一座真的城堡，被否定；第一輪的房間和鐵軌被認可，第二輪卻換掉了，又被指出 |
| 回到那個房間 | `rooms` | 一個主題是一間房。外殼照第一輪〈回到那個房間：五月到七月〉：娃娃屋、第一人稱走進一間真的房間、窗光、桌上和螢幕上是真實物品、回想時燈熄掉、片尾房子重新排列。房裡的真實物品（螢幕、紙、白板）演出主題的內容 | 適合分類、全景。第二輪〈九月〉改成抽象擺設（箱子、圓環、天平），使用者說跟原本的不一樣 |
| 線索板 | `board` | 一個主題是牆上的一個案件區：便條是重點，**證物照片、報告影本、平面圖**是筆記的圖和實例，線上寫關係；主題之間的線連到別的案件。整理過，不混亂 | 適合比較、互相牽連。真的線索板本來就有照片和圖解（使用者 2026-11-01） |
| 倒帶 | `rewind` | 一個主題是軌道上的一站。外殼照第一輪〈倒帶回四月〉：山林裡的鐵軌、季節跟著時間變、站是真實地點和當時的桌面。先看現在的結論，再倒帶回當初的問題和理由（只用筆記裡寫的） | 適合結論有來由、前後修正。少用：正向時間比較符合理解（使用者 2026-11-01） |
| 片子的順序 | | 片頭 → 全貌 → 主題段（4 個左右）→ 快問 → 結尾 | |
| 主題段 | `segment` | 片中呈現一個主題的那一段：進入 → 情境 → 問題 → 結構長出來（帶著做法、案例和圖）→ 判斷規則 → 回想 → 揭曉 → 收束 → 回到全貌。照筆記的顆粒度，約 2～3 分鐘（第二輪是 65～75 秒，太粗） | |
| 主畫面 | `main` | 畫面上最大的那一塊，給**真的東西**：筆記寫的程式碼、指令、表格、報告、數字，演出它怎麼運作。外殼（比喻）退到背景和轉場 | 借自 動畫課程製作手冊「主畫面是真的東西」；見 `04-演示.md` |
| 名牌 | | 寫著概念名字、卻什麼都沒演的道具或板子。要改成演出那個概念在做什麼 | 9 月房間 3 寫著「監督式」的藍色地墊；課程那邊叫「拍賣台加名牌」 |
| 畫面的檢驗 | `picture-test` | 驗收的另一半：遮掉字的定格給沒看過的人看，說得出每個畫面在演什麼機制才算過。和陌生人檢驗（只讀字）一起做 | 見 `04-演示.md` |
| 字的五種用途 | | 畫面上的字只用在：時間和情境、問題、判斷規則、回想和揭曉、貼在動作上的名字。其他說明都要演 | |
| 立牌測試 | `standee-test` | 遮掉字卡，只看主畫面：看得出機制、關係或差別才算過；只看得出「這是一面牆」就是立牌。和陌生人檢驗（只讀字）一起做 | 〈倒帶・十月〉第 3 站右邊是錄音帶和空白便條，沒過 |
| 主題演示卡 | `DEMO.md` | 每個主題寫分鏡前先寫：要帶走什麼、光讀字會卡在哪、主畫面演什麼真東西、理解發生的那一刻、立牌測試 | 借手冊的理解設計卡，縮小版 |
| 演示 | `demo` | 主畫面上把內容演出來：表格一列一列長出來、一筆輸出逐條被檢查、分數條越過門檻。字在一邊，演示在另一邊；外殼退到背景 | Rubric：價格表蓋上「任務完成」，三房那列被紅圈；權重 10 的必守規則還是被平均蓋過 |
| 證物 | `exhibit` | 放進外殼裡的圖或實物：照片、截圖、報告、程式碼影本、平面圖。線索板叫證物，房間是牆上的圖或桌上的藍圖，倒帶是停格的那一幀 | mutation 報告的截圖釘在第②關旁邊 |
| 回想 | `recall` | 其他東西暗下，只留一個問題，安靜倒數 6～8 秒 | |
| 揭曉 | `reveal` | 給答案，加上小字的筆記標題 | |
| 收束 | `wrap-up` | 一張圖加一句話把這個主題收起來，停 3～5 秒 | |
| 思考城堡 | `castle` | 一個主題是一座思考結構：打底（問題、定義、邊界）→ 上梁（因果、取捨把結構撐起來）→ 抗震（後來的修正、反例來搖，看哪根梁撐住）。**城堡是比喻**，不是真的蓋城堡 | 適合邏輯結構強、後來被修正或驗證過的主題。試驗中 |
| 自己設計 | `custom` | 四種都不合時，依內容自己設計外殼和演示 | 用學習原則和兩種檢驗驗收 |
| 「哇」的時刻 | | 一支片一到兩個讓人驚豔的畫面，最好來自內容本身 | 例：兩個主題原來連在一起 |
| 推論 | `inferred` | 不是筆記直接寫的內容（例如從時間推出來的情境），要標「推論」 | 外殼是比喻、字整理自筆記，片頭說一次就好，不用每段標 |

## 7. 製作

| 名詞 | 程式用名 | 定義 |
|---|---|---|
| 資料包 | `pack` | `collect.py` 的輸出：期間動過的筆記、初分的主題、canvas 圖 |
| 主題內容檔 | `CONTENT.md` | 全貌、每個主題的 10 項、快問。片子唯一的內容來源，任何風格都讀同一份 |
| 分鏡 | `STORYBOARD.md` | 每段的秒數、鏡頭、畫面上的東西、字、聲音 |
| 定格 | `stills` | 全解析度的關鍵畫面，審核用 |
| 兩階段 | | 先交主題內容檔、分鏡、定格，過陌生人檢驗和審核，才做全片 |
| 素材 | `assets` | 可以重用的東西：外殼的參考程式和參考圖（`assets/`）、配樂產生器、字型、canvas 畫圖程式 |
| 配樂 | `music` | 依情況挑的輕音樂。情況＝風格（房間／線索板／倒帶）＋段落（片頭／主題段／回想／片尾）；同一種情緒裡隨機，每支片不一樣，也不和上一支重複 | 不用〈Morning〉：那首是教學片的，回顧片用會撞（使用者 2026-11-01）。背景一律是樂音，不用底噪、嘶聲當氛圍 |
| 情緒 | `mood` | 配樂的分類：溫暖（房間）、好奇（線索板）、沉思（倒帶、思考城堡）、明亮（片尾）、思考（回想倒數） | 原型做法見 `06-片子規格.md` 第 5 節 |

## 8. 不再用的詞

| 舊詞 | 改成 | 為什麼 |
|---|---|---|
| 房間（當通稱） | 主題 | 見第 0 節 |
| 展示方式 | 風格 | 統一用使用者的說法 |
| 那時候 | 情境（一行） | 時間只當入口，不是內容 |
| 變化 | 修正 | 只算筆記裡自己寫的，不比對改動紀錄 |
