# 04 演示：把概念演出來


## 1. 最常犯的錯：把字放進 3D 空間

第二輪三支片都犯了：空間很漂亮，但空間裡的東西是**寫著字的板子**。藍色地墊寫「監督式」、牆上四張卡各一行字、錄音帶軌道旁邊畫著空白橫線的便條。把字遮掉，畫面只剩「這是一間房」。這叫**名牌**：一個道具貼著名字，什麼都沒演（課程那邊的說法是「拍賣台加名牌」）。

## 2. 原則

### 原則 1：每個概念都演出「它在做什麼」，名字只是貼在動作上的小標
先看到東西在動、看懂發生了什麼，名字最後才貼上去。

### 原則 2：從筆記的定義句找動詞，動詞就是動畫

| 概念 | 筆記的定義 | 動詞 | 演什麼 |
|---|---|---|---|
| 監督式學習 | 「人工標好的歷史正解」 | 對答案、修正 | 每筆過去的資料掛一張答案牌；模型猜、對答案、差多少就調一點，散點上的線慢慢貼合 |
| 非監督式學習 | 「沒有標籤，找資料自己的結構」 | 自己聚成群 | 一堆沒掛牌的點自己靠攏，聚成幾群 |
| 自監督學習 | 「資料自己出題考自己（遮一段猜回來）」 | 遮住、猜回來 | 一句話遮住一個詞，模型猜，打開對答案 |
| 強化學習 | 「只有好壞回饋」 | 試、得到好壞 | 一步一步試，每步後只亮好或壞，沒有答案牌 |
| LLM | 「骨子裡是超大規模分類（從幾萬個 token 選一個）」 | 從一大排裡選一個 | 一大排候選字選中一個，文案一個字一個字長出來 |
| Aggregate | 「只能經 Root 一個入口修改」「有併發才需要唯一入口＋版本號／鎖」 | 搶、擋下 | 同一秒兩個審核人按核准：先存的成功，後存的版本號對不上，被彈回來 |
| mutation testing | 「把 code 改壞一處……全綠＝Survived」 | 改壞、沒抓到 | `==` 翻成 `!=`，測試燈還是全綠 |
| 硬門檻 | 「一定要守的規則先判，不進加權平均；沒過直接不合格」 | 擋在前面 | 分數條越過門檻，前面那道門卻沒開 |
| 連線池爆掉 | 「需要的連線數＝每秒 25 張 × 每張占住 8.2 秒 ≈ 205，上限 100」 | 借走不還 | 一排 100 個插槽，訂單一張張進來占住不放，第 101 張開始排隊 |

### 原則 3：字只用在五種地方
1. 時間和情境（「9 月初，替採購系統寫規劃書」）。
2. 這個主題的問題。
3. 判斷規則（一針見血那一句）。
4. 回想題和揭曉的答案。
5. 貼在動作上的名字（小標）。

其他說明都要演。畫面上出現一段說明文字，就問：這句能不能演出來？

### 原則 4：主畫面放真的東西
主畫面是筆記寫的實物：程式碼、指令、終端機、表格、報告、真實數字、真實介面。外殼（房子、軌道、牆）是比喻，退到背景和轉場，不佔主畫面。只有真的畫不出來又難懂時才用類比，用完回到真實畫面。筆記沒寫的數字和細節標「示意」，不能畫得像真的紀錄。

### 原則 5：同一個畫面只改一個條件
例：四種學習方式不是四塊並排的牌子，而是**同一台機器**只換餵進去的訊號（有答案牌、沒牌、遮一格、只有好壞），一眼看出差別在哪。Rubric：同一筆輸出，必守規則放在平均裡 → 過；拉出去當硬門檻 → 不合格。

### 原則 6：筆記自己的圖是終點
演示一格一格演出來，最後停在筆記自己畫的那張圖上（例：〈兩軸模型全景〉整張亮起）。

### 原則 7：演示要幫你回答回想題
回想題問的機制，演示先把零件擺好；揭曉時讓動畫跑完，答案自己算出來（例：權重 10 的必守規則，分數條還是越過門檻 0.66 > 0.5）。

## 3. 圖型

| 內容的形狀 | 用的圖 |
|---|---|
| 過程、先後 | 流程圖（左到右，關卡、分岔、回圈） |
| 分層、一層擋一層 | 分層圖、漏斗 |
| 一個東西牽出很多 | 心智圖 |
| 對照、選擇 | 對照表、兩欄、同一畫面只改一個條件 |
| 實際長什麼樣 | 截圖、報告、程式碼影本、終端機 |
| 數字從哪來 | 每個數字背後的東西走一遍（連線、人流、版本） |
| 尺度、變大會怎樣 | 把看不見的量畫出來（資料表三個月從 420MB 胖到 14GB） |

可以借其他領域的能力：調查記者（從一個異常追出整個系統）、魔術師（先給不可思議的結果，再揭露被忽略的關鍵：測試全綠，條件卻被改反了）、科學家（改一個條件看結果分岔）、資訊視覺化（換一種排法差異自己浮現）。動畫也能給「不可能的經驗」：看得見連線被占住、幾個月壓成幾秒。

## 4. 主題演示卡（`DEMO.md`，寫字之前先寫）

每個主題：
1. 看完要帶走什麼（判斷規則、機制、做法）。
2. 光讀字會卡在哪（看不見過程、沒有尺度感、兩個概念混在一起）。
3. 每個概念一列：筆記的定義句 → 動詞 → 演什麼 → 遮掉字看得懂嗎 → 名字什麼時候貼上。
4. 主畫面放哪些真東西、哪些現成的圖，在外殼的哪裡演（房間的螢幕、白板、桌面；軌道的站；線索板的證物）。
5. 理解發生的那一刻（例：權重 10 的必守規則，分數條還是越過門檻）。
6. 畫面上每一段字屬於五種用途的哪一種；不屬於的改成演示。

範本：`templates/DEMO.md`。

## 5. 畫面的檢驗（立牌測試）

- 每個關鍵定格交兩份：有字、遮掉字（場景要有一個關掉字層的參數，例如網址加 `?notext=1`）。
- 遮掉字的那份交給沒看過的 agent（任務說明：`templates/畫面的檢驗.md`），請它說出每張在演什麼機制。說得出來才算過；只說得出「一間房」「一面牆」就是名牌，要改。
- 主持人審定格時，**先看遮掉字的那一份**，再看字的大小和遮擋。
- 常見的名牌：遠景（整面牆、整棟房子）沒有焦點；回想整個調暗；空白卡片、黑螢幕佔畫面中央。見 `08-經驗與避坑.md` 3.5 節。

## 6. 範例

### 6.1 AI 模型怎麼選（房間風格）
外殼照第一輪的真實房間，演示在房裡的大螢幕、白板和桌面上。

| 段 | 演什麼 | 字 |
|---|---|---|
| 情境、問題 | 走進房間，桌上的螢幕亮起 | 情境一行；「碰到一個業務需求，該用哪種 AI 模型？」 |
| 所有模型都在學同一件事 | 桌上一台小機器：資料進去，答案出來 | 小標 `f(輸入) → 輸出` |
| 學習方式＝訓練訊號從哪來 | 同一台機器演四次，只換餵進去的東西：掛答案牌的銷售紀錄（線貼合散點）／沒掛牌的客戶點聚成三群／一句話遮一個詞再猜回來／試一步只亮好或壞 | 動作做完才貼：監督式、非監督式、自監督、強化學習 |
| 輸出長什麼樣 | 出料口吐出：一個數字、一張分類標籤、一段正在打出來的文字、一串動作箭頭 | 數字、類別、新內容、決策 |
| 兩軸交叉 | 訊號圖示排成直的一排、輸出排成橫的一排，模型一個個落進格子，最後變成筆記的〈兩軸模型全景〉；空格保留 | 「格子空著是正常的」 |
| 哇：LLM 骨子裡是分類 | 推近 LLM：每一步在幾萬個候選字裡選一個；拉回來跟「分類」連線 | 「從幾萬個字裡選一個」 |
| 從業務倒推 | 需求卡「預測下個月賣多少」走過四道閘，落進「迴歸」 | 四道閘上的問題 |
| 回想 | 新卡「這位客戶會不會流失？」停在第一道閘前，畫面暗下 | 回想題 |
| 揭曉 | 卡片走完四道閘，落進「分類」 | 答案＋筆記標題 |
| 便宜的先擋 | 客服問題流進來，便宜的分類模型先接住約八成，分不出來的才給 LLM | 判斷規則 |

### 6.2 Rubric 評分量表（字卡在左，右邊演示）

| 左邊的字 | 右邊演什麼 |
|---|---|
| 結論：把「好」拆成能打勾的條目，合成分數 | 照筆記〈rubric零件與合成.svg〉的流程：一份輸出 → 硬門檻 → 逐條判 → 加權平均 → 跟門檻比 |
| 當初：公寓定價 AI 交出價格表，「任務完成」判通過，三房價格卻偏得離譜 | 價格表（數字標示意）蓋上「任務完成 ✓」；推到三房那列：比兩房還便宜，紅圈 |
| → 所以：用業務語言寫下「做對」 | Rubric 表一列一列長出來（筆記原文和權重 9、6、4、−8），每列拉線去檢查價格表，第 3 列連到三房打 ✗ |
| 回想：為什麼必守的規則，不能只把權重調高？ | 「不透露其他客戶資料」放進表裡給權重 10；這筆輸出洩漏了（✗），其他都 ✓；分數條停在半空，暗下 |
| 揭曉 | 分數條填到 19 ÷ 29 ≈ 0.66，越過門檻 0.5 亮「過」→ 紅光；把那條拉到最前面當硬門檻：✗ → 整份不合格 |

### 6.3 AI coding 品質防線（線索板）
主線案子用筆記裡的採購預測系統：先列出 AI 最可能闖的禍（人工改過的數字被同步蓋掉、計算邊界、重複計算），每一關都用紅線連回它擋的是哪一條。證物：必跑指令的終端機影本、架構規則的錯誤訊息、mutation 報告截圖（守衛條件被改反，測試全綠，AI 還說「只影響 log」）、`RuleFor` 三行、「同一句規則講三次」的分層圖、筆記自己的〈光譜〉圖。
