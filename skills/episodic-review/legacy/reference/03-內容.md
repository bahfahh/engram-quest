# 03 內容：從筆記到主題內容檔

## 1. 選範圍

```bash
python3 .claude/skills/engram-quest-episodic-review/scripts/collect.py --vault . --start 2026-10-01 --end 2026-10-31 --out <輸出資料夾> --render
```

- 輸出 `pack.json`、`topics/<主題>.md`（每個主題：筆記清單、canvas 圖路徑、每篇的總結句、反向連結）、`canvas_png/`。
- 規則已寫在程式裡：學習日以台灣時間凌晨 5 點切；整庫搬家（一次改名 30 個以上，或一次動 150 個以上）不算動過；改名前的舊路徑會對回現在的路徑。
- canvas 畫圖要中文字型：系統沒有時設 `CANVAS_FONT_DIR`（指到 `@fontsource/noto-sans-tc` 的資料夾）。
- 初分的主題要再合併：同一件事的資料夾合在一起（共用同一張 canvas、互相連結很多）。
- 作品檔（例如做影片時的 CARD／SCRIPT／NOTES）先排除，不當學習內容。

## 1.5 有 Obsidian CLI 時先用它（比較快、比較準）

Obsidian CLI（官方，1.12 起）用 Obsidian 自己的索引：連結會照 Obsidian 的規則解析（別名、改過名的檔案、同名筆記），搜尋支援 `tag:`、`path:` 這些語法。**前提是使用者的 Obsidian 開著、設定裡開了命令列介面**；雲端環境通常沒有，就退回下面的程式和 grep。

| 要做的事 | 有 CLI | 沒有 CLI（退回） |
|---|---|---|
| 期間動過哪些筆記 | `collect.py`（git 最準；檔案修改時間會被同步改掉） | 同左 |
| 整個 vault 的連結、反向連結、嵌的圖、標題、標籤 | `obsidian eval code="$(cat scripts/obsidian_index.js)" > index.json`，一次拿到 | `collect.py` 用規則運算式自己解析 |
| 某個主題被哪些筆記連到（找專案筆記、案例） | `obsidian backlinks file="<筆記名>"` | `grep -rl` |
| 找主題相關的筆記 | `obsidian search query="path:3.專案 Aggregate" limit=20 format=json` | `grep -rli` |
| 標籤分布（輔助分組） | `obsidian tags sort=count counts` | 自己數 |
| 讀筆記全文 | 直接讀檔（一樣快） | 同左 |

- 先跑 `obsidian help` 確認指令和版本；出現 Unknown command 表示版本太舊。
- `obsidian_index.js` 只取 Obsidian 索引裡現成的資料（同步、不讀檔），每篇的總結句和 canvas 內容另外直接讀檔。
- 這個 skill 在雲端做的第一輪到第三輪都沒有 Obsidian，所以用的是退回的做法；第三輪每個對照 agent 約 70 次工具呼叫，大多花在 grep 找反向連結和專案筆記，CLI 可以省掉這一大段。
- 雲端 session 如果接上使用者電腦的資料夾（Remote Control），也可以在使用者電腦上跑 CLI。

## 2. 讀：主題要完整，看筆記現在的樣子

- **一個主題拿整組**：這個月只動了一篇，也要把這個主題的其他筆記（其他天、其他月）一起讀。
- **整篇讀**，不切句子。先讀每篇的一句話總結、大綱、表格，再讀內文。
- **canvas 先看圖**：群組、箭頭、連線上的字，就是使用者自己整理好的結構，直接用。
- **連結兩邊都看**：這篇連出去的，和別篇連回來的。特別找：
  - 連到這個主題的**專案筆記**（例：`3.專案/` 裡把它用在真實專案上的筆記）：這是最好的案例來源。
  - 職人知識庫裡整理成規則的版本。
  - 複習卡（`engram-review/ai-cards/`）裡的圖解：是從筆記整理出來的，可以用；檔頭寫明是 AI 生成練習卡、沒有來源筆記的，不當事實。
- **中間怎麼改不看**；觀點修正只用筆記裡自己寫的。
- **禁止讀取或引用 `Clippings/`**（使用者規定：那是網路上爬的原始資料）。
- **不懂的名詞先上網查清楚再寫**（使用者規定）；先查完筆記，再一次查網路比較有效率。

## 3. 顆粒度：筆記寫到哪一層，片就講到哪一層

| 層 | 內容 | 例子（AI coding 品質防線） |
|---|---|---|
| L1 名稱 | 有哪些 | 四道關卡 |
| L2 概念 | 每個是什麼、防誰、為什麼 | 第②關防改程式的人和 AI；第③關防外面的輸入 |
| L3 做法 | 實際怎麼做：步驟、指令、規則的寫法、範例程式、清單 | 每次改完必跑的三行指令；`RuleFor` 三行；基礎設施 → 政策 → gate |
| L4 案例 | 用在一個真實的案子上，長什麼樣、擋下了什麼 | 採購系統的風險清單；mutation 報告：守衛條件被改反，測試還是全綠 |

**規則**
1. **主線講到筆記最深的那一層。** 筆記有 L3 就講到 L3；有 L4 就用它當主線。筆記只到 L2，就只講到 L2，不自己補。
2. **用一個案子串起來**：從筆記挑一個具體的案子（專案、事故、一條規則），讓它走過整個結構，概念跟著案子出現。
3. **做法要能照著做**：要跑什麼、規則怎麼寫、失敗時看到什麼。程式碼挑最短、最能說明的 3～6 行。
4. **深度優先**：片長不夠時少走一個主題，不要每個主題都削到只剩名字。沒走進去的主題留在全貌。
5. **主線深，旁支一行**，不把整篇搬上去。

**從筆記判斷顆粒度的訊號**
- L3：程式碼區塊、指令、步驟編號、核取清單、「實戰」「範例」「怎麼做」段落、prompt 範本、有「做法」欄的表格。
- L4：連過來的專案筆記、有數字和前因後果的事故、報告截圖、失敗模型。
- 圖：筆記嵌的 SVG／PNG（`![[...]]`）、mermaid、canvas、複習卡的圖解。

第二輪三支片的 12 個主題，片上全部停在 L1～L2，筆記全部至少 L3、一半 L4。這是最常犯的錯。

## 4. 圖：先用筆記自己的

順序：筆記嵌的圖 → canvas 畫成的圖 → 筆記的 mermaid 和表格（照它重畫）→ 都沒有才照筆記內容畫。

- SVG 裡的字常只有 11～14 級，縮在畫面上讀不到：當縮圖放，輪到它時推近到快占滿畫面，另算閱讀時間（約 7 秒一張）。
- 大張 canvas 不整張放，每個主題只裁一組；窄長的適合當路線圖。
- 截圖上有金鑰、真人頭像的，上片前遮掉或裁掉。

## 5. 每個主題的 10 項（`CONTENT.md`）

1. **問題**：這個主題在回答什麼，白話一句。
2. **結構和重點**：照筆記自己的結構（canvas、地圖順序、表格），3～5 點，每點一兩句白話；術語第一次出現用一句話說明。
3. **做法**（L3）：筆記寫的實際做法，寫到看完能動手。
4. **案例**（L4）：主線案子在這個主題裡長什麼樣、擋下了什麼。
5. **圖**：要放的圖和圖型，附路徑。
6. **判斷規則**：「怎麼選」「什麼時候用」，一針見血的一句。
7. **修正**：筆記裡自己寫了前後判斷不同才放。
8. **先問後給**：1～2 題，問道理；寫出答案的線索在哪裡先出現。
9. **未解問題**：筆記裡寫了、還沒定的事。
10. **情境**：一行，給本人的入口（「8 月底，對照之前 SampleApp 專案的做法」）。

另外：**出處**（筆記標題，給審核用；片中只在揭曉時小字放標題，不放路徑）、**全貌**（期間全部主題，每個一句「它在回答什麼」，加主題之間怎麼接）、**片尾快問**（2～3 題，拿掉外殼和情境再問一次，問為什麼）。

範本：`templates/CONTENT.md`。

## 6. 事實要對

- 每個數字照公式自己算一次，前後畫面一致。
- 不把設計意圖說成已經發生（例：筆記寫「這道關卡設計好了、還沒有」，片上不能說「醜的在這關就擋下」）。
- 標清楚來源性質：課程裡的情境標「課程案例」；官方文件的範例標「官方範例」；筆記沒寫的數字標「示意」。
- 兩個不同的切法不要說成同一種（例：Hindsight 的「證據 vs 信念」和 Google 影片的「事實 vs 理解」）。
- 筆記之間互相矛盾時，不替使用者選，做成「懸案」或列給使用者決定。

## 7. 字的檢驗（陌生人檢驗）

寫完 `CONTENT.md` 和片上的字後，交給一個沒讀過這些筆記的 agent（任務說明：`templates/字的檢驗.md`）。它只讀字，用自己的話講回每個主題的問題、結論、為什麼，並回答回想題。講不回來的地方要改。

第一次常見的問題：
- 讀不完（給的時間不夠）。
- 名詞沒解釋、指代不清（「這個範本」「四環」）；同一個東西混用好幾個詞。
- 只給結論，沒有因果。
- 回想題考沒教過的東西：答案的關鍵詞在揭曉時才第一次出現。
- 為了字數上限把句子壓成電報。
