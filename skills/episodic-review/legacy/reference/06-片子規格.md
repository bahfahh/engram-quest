# 06 片子規格

## 1. 結構（順序固定，比例自訂）

1. **片頭**（4～6 秒）：一句話「畫面是比喻；字都整理自你的筆記」，加一句「想多想一下，隨時按暫停」。
2. **全貌**（12～20 秒）：這段期間的全部主題攤開，每個一句；要走進去的主題標出來。轉場和片尾都回到全貌，讓人知道現在在哪。
3. **主題段**（每個 2～3 分鐘）：進入 → 情境一行 → 問題 → 結構和演示一步步長出來（帶著做法、案例和圖）→ 判斷規則 → **回想** → **揭曉** → **收束**（主題的結構圖＋一句話，停 3～5 秒）→ 回到全貌。
4. **片尾快問**（2～3 題）：拿掉外殼、情境、時間，再問一次；問為什麼，不問背句子。
5. **結尾**：回到全貌，全部亮起，完成的樣子；主題之間的關係線亮起（標出指向「→ 哪個主題」）。

## 2. 閱讀時間和字

- 沒有旁白，字要讀得完：每段時間 ≥ 新出現的總字數 ÷ 5，每張卡再加 1.5 秒；程式碼影本每行約 2 秒；推近看一張圖約 7 秒。
- **讀得到的時間才算**：字在畫面上，不等於讀得到。鏡頭推拉、景深轉換、換站時，字可能太小、在焦點外、被切到。每張字卡在出現期間，要有一段連續夠長（≥ 字數 ÷ 5 ＋ 1.5 秒）的時間是清楚、在畫面內、夠大的。`onscreen.py` 只量得到出現時間，這一項要看定格（每 0.5 秒一張半解析度）或在場景裡檢查。
- 「卡」：7 字以上的字算一張卡（加 1.5 秒）；2～4 字的小標不加 1.5 秒，但字數照算。
- 一般卡 ≤ 20～25 字；一定要說完整的卡（懸案、例子、機制、關係線）可到 40～60 字，時間照公式加長，**不要壓成電報**。
- 字只用在五種地方（`04-演示.md` 原則 3）。
- 名詞、專案名、角色名第一次出現，畫面上就有一句白話；指代要點名；同一個東西全片只用一個詞。
- 重點字至少 40px，其他至少 28px；全景鏡頭的小字不能是重點；畫面底部約 140px 不放重要內容；不要有被畫面邊緣切掉一半的大字、只剩一個字的換行。
- 第二人稱「你」，用影片語言自然的說法（第 2.5 節）。中文片用繁體中文、台灣用語；霞鶩文楷會把「為」畫成「爲」，含「為」的句子用思源黑體。
- 不放：檔名、路徑、幾點幾分、複習評分、「誰改的」。日期只在情境那一行，只到「8 月底」「9/4 那天」。
- 畫面上的字集中放在一個資料檔（含出現時間），方便抽出來做字的檢驗。

## 2.5 影片語言

語言的決定順序見 `SKILL.md`。`scripts/film_lang.py` 印出結果；`notes` 列出該語言還沒準備好的項目，照著補或在 `NOTES.md` 記下，不用停下來。

| | 繁體中文 | 英文 | 其他語言 |
|---|---|---|---|
| 閱讀單位 | 每秒 5 字，7 字以上算一張卡 | 一個詞算 1.75 字（每秒約 2.9 個詞，4 個詞以上算一張卡） | 中文、日文按字，其他按詞；速率沒校正過，靠定格讀一遍確認 |
| 外殼的介面字 | 內建 | 內建 | 在外殼內容檔的 `UI_SETS` 加一組，否則顯示英文並印出提示 |
| 旁白聲音（有旁白時） | `zh-TW-HsiaoChenNeural` | `en-US-AndrewMultilingualNeural` | 從 `edge-tts --list-voices` 挑，聽過再用 |
| 字型 | 專案字型 | 專案字型的拉丁字母 | 專案字型涵蓋拉丁、西里爾、越南文和繁中；其他文字要自己放字型進專案，不能靠系統字型 |

- **語言要傳到每個會用到它的地方**：外殼內容檔的 `LANG`、`film.json` 的 `lang`（或 `onscreen.py --lang`），值用 `film_lang.py` 印出的 `lang`。自己設計外觀的片不用外殼的 `LANG`，但要算閱讀時間就一樣走 `film.json`。
- **同一件事換語言是重新排版，不是換字**：拼音文字表達同樣的意思要用更多字元，同一句話佔的版面約是中文的兩倍。字卡寫短一點，並用定格確認沒有溢出、沒有被切，寫死的換行和固定寬度要跟著改。卡片、標籤、短牌的字數上限照中文估的，換語言要重新看。
- 閱讀時間照新語言重算：字量和版面都變了，段落秒數和鏡頭的焦點時間不能沿用。
- 片上的字照那個語言的講法寫，不是逐句翻譯；回想、快問在任何語言都問道理。
- 字的檢驗要用影片語言做。

## 3. 回想和揭曉

- **回想**：其他東西暗下，只留一個問題（和演示擺好的零件）；讀題時間＋6 秒安靜倒數。片尾快問一樣。
- **揭曉**：字數連筆記標題一起算，至少停 8 秒，其他東西暗下；可以讓演示跑完，答案自己算出來。
- **線索先上牆**：回想和快問的答案用到的關鍵詞、機制，要在提問之前出現在畫面上。
- 「當初 → 所以」：當初必須是這個結論真正的來由，不是旁邊的故事。
- 收束用主題的結構圖（心智圖、流程圖、筆記自己的圖），不是一行一行的字。

## 4. 片長

- 分短（1 個主題，約 2～4.5 分）、中（2 個，約 5～8 分）、長（3 個，約 8～13 分，完整），**只有這三個選項**。**片長是範圍，不是固定秒數**；三檔也是 AI token 花費的檔位（越短越精簡、檢驗越輕）。怎麼選、怎麼指定、插件設定、成本，看 `10-片長與成本.md`（數字在 `templates/length.json`）。
- 一個主題約 2.5～3 分鐘，照筆記的顆粒度。
- **深度優先**：片長要壓住時，少走一個主題，或只留主線、旁支留在筆記；不要每個主題都削淺。沒走進去的主題留在全貌，並列進「沒選的主題」清單，下一支再做。

## 5. 聲音和配樂

- 目前沒有旁白（這個雲端環境擋了語音合成）；在可以合成語音的環境，旁白要跟畫面講同一件事，聲音、字幕和語音辨識都用影片語言（第 2.5 節）。
- **配樂依情況挑**，不用〈Morning〉（那首是教學片的，回顧片用會撞）：
  - 風格決定情緒：房間溫暖、線索板好奇、倒帶和思考城堡沉思、片尾明亮、回想倒數用「思考」（極稀疏，停在沒解決的和弦上）。
  - 段落決定強弱：片頭片尾有旋律；主題段很淡但仍是樂音；回想退到最低；揭曉一聲乾淨的鐘。
  - 同一種情緒裡隨機，每支片不一樣，也不和上一支重複。
  - 用 `scripts/music/`：`pick_music.py` 依風格、段落、片 id 挑情緒和 seed；給一份 cue sheet（每段的秒數和段落種類，例 `examples/cues_rooms.json`）加 `--render`，就產生每段的 wav 和對齊時間軸的 `score.wav`，以及 credits。用法看那裡的 `README.md`。
  - 配樂是用真實樂器取樣即時作曲（Salamander 鋼琴 CC BY 3.0、FluidR3 音色 MIT／CC BY 3.0），每支片的調、速度、旋律都不一樣；`meta.json` 的 `credits` 照 `cues.json` 裡的文字寫。
  - 也可以放有授權的真曲子進 `scripts/music/library/`，在 `library.json` 標情緒和授權；標 `course` 的（〈Morning〉）不會被選。
  - 混音：`score.wav` 加上少量音效，混成專案的 `narration.wav`。
- **背景一律是樂音**：不用錄音室底噪、錄音帶嘶聲、馬達聲這類雜訊當氛圍。音效只用有音高、乾淨的（鐘、撥弦一聲、木頭碰撞），而且只在該有的那一下。
- 響度：整體約 −16～−17 LUFS，true peak < −1 dB；中間很安靜時 −17 也可以，寫理由。配樂不要從頭到尾一樣大聲。

## 6. 覺得很棒

- 真的空間（three.js）、材質、光影、季節、景深、真的鏡頭運動；拒絕投影片式淡入淡出、拒絕把網頁 UI 搬進影片。
- 一兩個「哇」的時刻，最好來自內容本身（例：兩個主題原來連在一起；LLM 骨子裡是分類）。
- 停頓有長有短：提問後真的等，揭曉後讓畫面說話。
- 外觀和氛圍跟內容一樣重要：第二輪內容比較好，外觀和氛圍卻沒第一輪好，使用者明確指出。
