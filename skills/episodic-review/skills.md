# engram 情境記憶回顧片

## 一句話

**內容為王，外觀要美，概念要演出來。** 先讀懂筆記現在的樣子、以主題為單位整理完整；再依內容選外殼（或自己設計）；畫面把每個概念演出來，字只當標籤。

## 要達成什麼

看完的人會：
1. 重新思考、回憶。
2. 結構清晰，一個主題一個單位。
3. 看完有思考，或幫助記憶（情境記憶）。
4. 覺得很棒：畫面和氛圍要好看。

驗收兩半都要過：
- **字的檢驗**（陌生人檢驗）：沒讀過這些筆記的人，只讀片上的字，講得回每個主題在回答什麼、結論、為什麼。
- **畫面的檢驗**（立牌測試）：遮掉字，只看畫面，說得出每個畫面在演什麼機制。

## 和動畫課程（教學片）的分別

| | 情境回顧片（這個 skill） | 動畫課程 |
|---|---|---|
| 目的 | 把**你自己學過的**主題叫回來 | 學會使用者想學的東西：範圍由使用者決定（整門課、幾課，或只補一個概念），預設 Ultralearning 的學習設計 |
| 內容 | 只有筆記現在的樣子，不加筆記以外的東西 | 教材，可以查證補充 |
| 時間 | 有時間維度：期間選範圍，情境一行當入口 | 沒有 |
| 單位 | 主題 | 一課 |
| 外殼 | 房間、軌道、線索板、思考城堡，或自己設計 | 教室、老師、課程地圖 |

不借課程的教室、老師、課程地圖；但讓人看懂的畫面手法一樣適用（主畫面放真的東西、立牌測試、把機制演出來），已經寫進這個 skill 的 reference，不用去讀課程的文件。

## 和 engram-quest 插件怎麼分工

| | 這個 skill | 插件（待做，設計在 ticket） |
|---|---|---|
| 負責 | 讀筆記、選主題、做片、交付 | 在「記憶」類別的分頁列出、播放、記進度；設定預設片長；按鈕建立「做新的一支」的要求 |
| 資料 | 寫 `engram-quest/videos/episodic-recall/meta.json` 和影片檔（`scripts/deliver.py`） | 讀同一份 `meta.json`；播放進度寫回 `progress` |
| 觸發 | **兩條路**：使用者直接對 Claude 說；或使用者在插件按「做新的一支」，插件把一筆 `pending` 要求寫進 `meta.json` 的 `requests` 並複製提示，使用者貼給 Claude | — |

- 步驟 0 先看 `meta.json` 的 `requests`：有 `pending` 的，期間和片長照它的；交付時 `--request-id` 把它標成 done。
- `meta.json` 的欄位約定（`period`、`length`、`topics`、`notTaken`、`credits`、`createdAt`，系列層的 `kind: "episodic"`）不要改名；插件的 UI 讀這些。
- 完整設計：vault 的 `feature/feature-2026-11-02-episodic-review-plugin.md`。

## 流程

| 步 | 做什麼 | 讀哪份 |
|---|---|---|
| 0 | 讀懂這個 skill 的觀念；看 `episodic-recall/meta.json` 有沒有插件寫的 `pending` 要求（有就照它的期間和片長） | `reference/01-基本觀念.md`、`reference/02-名詞與定義.md` |
| 1 | **選範圍**：`scripts/collect.py` 找出期間動過的筆記，初分主題，畫 canvas 圖；Obsidian 開著時用 Obsidian CLI 拿連結和反向連結 | `reference/03-內容.md` 第 1、1.5 節 |
| 2 | **讀內容**：一個主題拿整組筆記，看筆記現在的樣子；找出顆粒度（做到哪一層）、主線案子、現成的圖 | `reference/03-內容.md` 第 2～4 節 |
| 2.5 | **問使用者要哪一檔（短／中／長，只有這三個）**：三檔是 AI token 花費的檔位，片長是範圍；越短，主題越少、精緻度越低（用現成外殼和演示、檢驗從簡）、算得越快。使用者這次已經說了就照說；沒說就在讀完內容後用 `AskUserQuestion` 問一次（每個選項附主題數、片長範圍、session 數、時間、相對 token，建議的放第一個）；不能問時讀插件設定 `episodicLength`，沒有就用「中」。主題照排名自動挑 | `reference/10-片長與成本.md`、`templates/length.json`、`scripts/length_estimate.py` |
| 3 | **寫主題內容檔** `CONTENT.md`：全貌、每個主題 10 項、快問；做字的檢驗 | `reference/03-內容.md` 第 5～7 節、`templates/CONTENT.md` |
| 4 | **選展示方式**：讀懂內容後才選。四種外殼可以選，也可以都不選、自己設計更好的；一支片可以混用 | `reference/05-風格.md` |
| 5 | **設計演示** `DEMO.md`：每個概念演什麼（從定義句找動詞）、字只用在五種地方 | `reference/04-演示.md`、`templates/DEMO.md` |
| 6 | **分鏡和定格**：`STORYBOARD.md`；關鍵定格交有字、遮掉字兩份；做畫面的檢驗 | `reference/06-片子規格.md`、`reference/07-製作與工具.md` |
| 7 | **使用者審第一階段**（內容、演示、定格）後才做全片 | `reference/07-製作與工具.md` 第 1 節 |
| 8 | 全片：動畫、配樂、分段算圖（依片長 1～3 個雲端 session）、檢查 | `reference/06-片子規格.md` 第 5 節、`reference/07-製作與工具.md` |
| 9 | 交付到 `engram-quest/videos/episodic-recall/`，記錄使用者的回饋 | `reference/07-製作與工具.md` 第 5～6 節 |

做之前先讀 `reference/08-經驗與避坑.md`：前兩輪犯過的錯都在那裡。

## 影片的語言

片上的字、回想和快問、旁白和字幕都用同一個語言，依序看：使用者這次說的 → `engram-quest/videos/settings.json` 的 `narrationLang`；`follow` 或沒設定時用來源筆記的語言，筆記分不出來就用使用者打字的語言。讀完筆記後（步驟 2）確定，用 `scripts/film_lang.py [--lang <語言>]` 得到結果和該語言還缺什麼，再把語言交給要用它的地方（`reference/06-片子規格.md` 第 2.5 節）。這份 skill 的文件維持中文；影片語言只影響片子本身。

## 不能違反的規則

1. **看筆記現在的樣子**。中間怎麼改不看；修正只看筆記自己寫的。
2. **主題要完整**：期間只選範圍；某個主題這個月只動一篇，也要拿整組筆記。
3. **陌生人看得懂**：名詞第一次出現就有一句白話；不放檔名、路徑、幾點幾分、評分。
4. **顆粒度跟著筆記**：筆記寫到做法和案例，片子就講到做法和案例；筆記沒寫的不補。
5. **把概念演出來，不是貼名牌**：字只用在時間和情境、問題、判斷規則、回想和揭曉、貼在動作上的名字。
6. **主畫面放真的東西**（筆記裡的程式碼、表格、報告、數字），比喻的外殼退到背景。
7. **先讀內容再選展示方式**，不硬套；認可過的外殼照用，不重新設計。
8. **背景一律是樂音**，不用底噪、嘶聲當氛圍；不用〈Morning〉（那首是教學片的）。
9. **不讀 `Clippings/`**；不懂的名詞先上網查清楚。
10. 一定要有先問後給：問道理，停下來等，再揭曉；答案的線索要先出現在畫面上。
11. **短是少做精緻，不是少講內容**：想短就少走主題、用現成外殼和演示、檢驗從簡；每個走進去的主題仍走到筆記最深的那層、有演示、回想和揭曉。片長是範圍，不是固定秒數。沒選的主題留在全貌當紋理，並列進「沒選的主題」清單。

## 發現插件或 skill 的問題

使用者是 engram-quest 的開發者。發現插件或這個 skill 的錯（路徑錯、腳本錯、描述不清），先確認，再照 vault 的 `AGENTS.md` 在 `debug/` 開 ticket，並告訴使用者。
