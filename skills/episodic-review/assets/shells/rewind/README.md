# rewind 外殼（倒帶）：〈倒帶回十月〉生產版

來源：第三輪 ep-oct〈倒帶回十月〉，外觀和演示都是**認可過的**，照用，不要重新設計。上一版（第一輪〈倒帶回四月〉）已被取代，要看就查 git 歷史。

## 一、這個外殼給你的樣子

- **低多邊形山林鐵軌**，只走一個月、時間正向（倒帶只用在片頭，一次倒回月初）。鐵軌上的季節會變色（十月：綠 → 黃 → 褐），樹葉在倒帶時往上飛。
- **開頭**在月底的夜裡從高處看全貌：一道光帶沿鐵軌從月底掃回月初，掃到哪一站、那一站的光柱才亮；接著是一塊時刻表（要停的站一列列亮起，旁邊的小縮圖先預演動作）。
- **每一站是鐵軌旁的剖面小屋**：一張真的工作桌（螢幕、窗、檯燈、軟木板、書架、筆筒、盆栽），窗外有畫好的天空和山。三站三種光（傍晚金光、黃昏紫橘、夜裡檯燈）。**演示都發生在螢幕和紙上**，外殼退到窗外和轉場。
- **一站的節奏**：抵達（站牌一行情境）→ 窗上的問題便條 → 演示 → 回想（燈熄、只剩螢幕亮、倒數 6 秒）→ 揭曉 → 軟木板收束（三張證物拉紅線、長出小心智圖、懸案便條釘進空位）→ 快轉離開。
- **片尾**：拿掉情境再問兩題，最後回到和片頭同角度的全貌，站與站之間畫金線。
- 約 10 分 10 秒（609.9 秒）、1920×1080、24 fps、三站。

## 三、換內容的地方

先說清楚：這份程式**不是設定檔驅動**，站數是寫死在好幾個檔案裡的 3 站。換內容主要改 `content.js` 和 `demos.js`，換站數要動多處（下表）。

| 要換什麼 | 改哪裡 |
|---|---|
| **語言和介面字** | `content.js` 開頭的 `LANG` 是影片語言，`UI_SETS` 是固定的介面字（片頭提示、倒帶、快轉、日期牌格式、快問）。換月份時 `date` 要一起改 |
| **換語言時要自己改的字** | `demos.js`：`priceTable` 的表頭和 `ROWS`、`docT` 的「做片規則」。內容字串裡用來切開的 `｜`、`／`、全形空格要留著；`nowrap` 的字變長會溢出，要改字級或寬度；`assets/*.svg` 裡的字要換 |
| **文字**（站牌、問題、小標、回想、揭曉、原話、軟木板的規則句和懸案） | `content.js` 的 `TXT`：`S(id, t0, t1, text, 用途, 位置)`。畫面上每個字都是 `tx(id)` 讀來的，`t0/t1` 照所屬那一拍（`b1.five`、`b2.rows`…）相對寫 |
| **每一拍的秒數** | `content.js` 的 `beats([['arr', 9.5], ['q', 5.5], …])`，每站一個（`B1/B2/B3`）。秒數要照字數算（字數 ÷ 5 ＋ 每張 7 字以上的卡 1.5 秒；回想＝讀題＋6 秒；揭曉 ≥ 8 秒）；倒數 `B*.cd` 跟著回想那拍 |
| **螢幕內容（演示）** | `demos.js`：站 1 `buildS1R`（右螢幕，900×506）、`buildS1L`（左螢幕）、站 2 `buildS2`（1280×720）、站 3 `buildS3`（超寬 1560×667）。每個回傳 `{ el, update(t) }`，`update(t)` 只看 t，用 `mode` 依拍切換子畫面。可重用的演示見 `assets/demos/_ep-oct.md` |
| **軟木板收束** | `demos.js` 的 `buildCork(key)`：`SRC`（三張來源圖或小圖）、`NODE`（三個小縮圖）、`key_rule`（規則句）、`key_open`（懸案）；圖放 `assets/` |
| **站牌、問題便條** | `buildSign`、`buildNote`（文字走 `TXT` 的 `sN_date/_name/_ctx/_q`） |
| **時刻表和全貌標籤** | `buildBoard` 的 `rows`（`tt_r1..3`、對應的 `pic*` 小縮圖）；全貌站名標籤 `pin1..3` 在 `TXT`，scene.html 的 `pins` |
| **鏡頭劇本** | `scene.html`：每站固定機位 `POSE[k]`（`SIGN/EXT/IN/Q/DESK/CORK/WIDE`，在小屋本地座標）；每站的 `visit('s1', B1, …, p => { add(t0, t1, A, B) … })` 把每一拍接上機位；`drift()` 是慢推。**加一個演示拍，就要在這裡加一段鏡頭** |
| **焦點與景深** | `focusAt(t)`：問題便條要清楚到 `q+5.6`，之後才把焦點拉到螢幕（見下方踩過的坑） |

## 四、怎麼試

```bash
STUDIO=<工作區>            # 已有 render.cjs、node_modules（見 legacy/reference/07-製作與工具.md 第 3 節）
cp -r .claude/skills/engram-quest-episodic-review/assets/shells/rewind $STUDIO/projects/<id>
cd $STUDIO
RENDER_GPU=1 node render.cjs projects/<id> --stills 156      # 一張定格 -> projects/<id>/stills/t-156.jpg
```

- 這個外殼只讀專案資料夾和 `/node_modules`，不需要 `/lib/stage.js`，所以直接複製就能算。
- 站內時間點（原片 10 月）：82.6 問題便條、93.6 關卡管線、156 並排比對、288 分數條、531 卡匣；全貌 15。
- WebGL 一律 `RENDER_GPU=1`。全片分段算（見 reference/07）；原片實測每格約 1～2 秒（機器負載高時 2 秒以上）。
- 遮字版定格：`--scene "scene.html?notext=1"`。注意有字和遮字版同一秒會寫成同一個檔名，算完要自己搬。

## 五、已經踩過的坑

- **SwiftShader（無 GPU）下 CSS `filter: blur` 會讓同一層旁邊的元素整張漏畫**（遮字版軟木板少了卡片）。模糊一律在載入時用 2D canvas 先做好，不要用 CSS 濾鏡。
- **`studioReady` 不能太早 resolve**：要等全部 `<img>` decode 完、字型載完。否則分段算的每段第一格會缺圖。
- **問題便條實際只讀得到約 2 秒**：閱讀檢查全過，因為它只算「出現」，不算「在焦點內」。現在鏡頭提早 0.6 秒進屋、`q+0.8` 到便條前，焦點留到 `q+5.6` 才拉到螢幕，三站各清楚約 5.5 秒（需要 4.1～4.5）。改鏡頭或秒數後，用 `assets/tools/clarity-ep-oct.cjs` 重量一次，並**在每個字卡出現的時段抽定格看**（它只量得到 DOM 字，量不到 3D 貼圖上的字）。
- **繼承的可見性**：子元素 `visibility: visible` 會在隱藏的父元素下照樣出現。切換一律用 `display`（程式裡的 `show()`，原本的 display 存在 `dataset.d`）。
- **窗外天空被地形擋住**：畫好的天空貼片放在 z -10.5，只在那一站屋裡才開；離站鏡頭先退到屋外高處再下軌道，否則會穿牆、天空變成立在野外的板子。
- **窗外只看到天空**：桌前鏡頭只看得到貼片上緣。山和樹要往上移到窗看得到的高度，太陽月亮也調低進窗。
- **快轉到站整片過曝**：光球光暈和到站閃光要依與鏡頭的距離縮小變淡，不能照全貌的尺寸。
- **在同一行程式中間加 `//` 會把後面的程式一起註解掉**（第二段快轉鏡頭跳到高空）。要註解用 `/* */`。
- **字溢出**（1920 寬折行或超出螢幕）：手動 `\n`、`nowrap`、便條自動寬度、縮字級。
- 字型走 `/node_modules/@fontsource/`；**`assets/*.svg` 內有中文，當 `<img>` 載入時用的是系統字型**（`rubric-flow.svg`、`five-layers.svg`）。雲端算圖機的字型不同，要確保那台有 CJK 字型，或換新內容時先轉成 PNG（reference/07 第 3 節）。
- `--stills 14.0` 存成 `t-14.jpg`；`--stills 82.6` 存成 `t-82.6.jpg`。
- 閱讀時間檢查：現在統一用 `film.json` 和 `scripts/onscreen.py`（reference/07 第 3.5 節）。原片用的 `dump.mjs` 沒帶進來。

## 六、不要改（認可過的外觀）

- 低多邊形山林、鐵軌、季節變色、光柱與光帶、光球快轉。
- 剖面小屋與桌上物件的配置、三種光、窗外畫好的天空和山。
- 一站的節奏（先問後給、回想燈熄只剩螢幕亮、倒數 6 秒、揭曉回主和弦）、軟木板收束、片尾兩題與金線。
- 螢幕演示「發生在螢幕和紙上、外殼退到窗外」的分工。
- 景深做法（大景深時 3D 半解析度加 CSS 模糊）、`renderAt(t)` 是 t 的純函數。

可以換的是內容：站、字、演示、圖、月份與季節色、時段光的組合。改任何機位前先算定格對照原片，不要連著動多個機位。

## 七、已知取捨與下一輪要試的

**取捨**：螢幕要讀得清楚，演示就得佔掉大半個畫面（例：288、328、531 秒的定格），這時房間只剩邊緣：窗光、檯燈、筆筒變成背景，氛圍變弱，看起來像「螢幕錄影加一圈邊」。並排比對（156 秒）因為是兩個螢幕，氛圍保得最好。

**下一輪試**：
1. 螢幕放在畫面一側（約 55～60% 寬），另一側留窗光、桌面前景物件（筆筒、盆栽、檯燈、一本翻開的筆記），字放大到夠讀（螢幕上的字高仍 ≥ 18 px）。這要新增一組「偏側」機位（`POSE[k].DESKSIDE`）；`demos.js` 的畫面不用改。
2. 演示進行時，讓房間的光跟著螢幕內容變：螢幕打勾變綠、打叉時桌面泛紅，用 `LIGHT[k].screenI` 加一個隨 t 變的色。
3. 兩案比較時先各算一張同一秒的定格，再用畫面的檢驗盲測，使用者覺得氛圍補回來、演示又沒變小才換。
