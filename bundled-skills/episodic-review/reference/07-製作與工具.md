# 07 製作與工具

## 1. 兩階段

**第一階段（做完就停，給使用者或主持人審）**
1. `CONTENT.md`：全貌、每個主題 10 項、快問（`03-內容.md`）。做**字的檢驗**，改到講得回來。
2. 選風格，寫理由（`05-風格.md`）。
3. `DEMO.md`：每個主題的演示卡（`04-演示.md` 第 4 節）。**演示先審過才寫片上的字。**
4. `STORYBOARD.md`：每段秒數、鏡頭、主畫面演什麼、字、聲音。
5. `scene.html` 先把外殼和主要演示建出來，算 6～8 張全解析度關鍵定格：全貌、兩個主題的演示畫面、一個回想、一個收束、結尾。**每張交有字、遮掉字兩份**，做**畫面的檢驗**。
6. 回報：檔位和估算（`scripts/length_estimate.py`：主題數、片長範圍、精緻度、session 數、時間、相對 token）、選了哪些主題和理由、**沒選的主題清單**、風格和理由、定格清單、最弱的地方。檔位已在步驟 2.5 問過，這裡不再另外確認。

**第二階段（審過才做）**：照意見修 → 完成全部動畫和配樂 → 片段預覽檢查 → 分段算全片 → `NOTES.md`（手法、怎麼做到四個感覺、遇到的問題）→ 交付。

## 2. 分工（多個 agent 時）

- **主持人**：寫任務說明、選範圍、審第一階段、派檢驗、交付、記錄使用者回饋。
- **製作者**：一支片一個；只在自己的專案資料夾寫檔；不 commit、不改 vault。
- **字的檢驗者**：沒讀過筆記的新 agent，只拿片上的字（`templates/字的檢驗.md`）。
- **畫面的檢驗者**：沒讀過筆記的新 agent，只拿遮掉字的定格（`templates/畫面的檢驗.md`）。
- 任務說明從「認可過的外殼和規則」開始寫，不寫「不要套上一輪」這類鼓勵整支重做的話；但要明寫哪些外殼是認可過、要照用的。

## 3. 算圖工具（`scripts/studio/`）

**準備工作區**（一次）：
```bash
STUDIO=<一個工作資料夾>
mkdir -p $STUDIO/projects && cp -r .claude/skills/engram-quest-episodic-review/scripts/studio/. $STUDIO/   # render.cjs、package.json、lib/stage.js
cd $STUDIO && npm install            # three、gsap、字型、lucide 圖示
# 需要 Playwright 的 Chromium（node 可 require('playwright')）和 ffmpeg
```
每支片的專案放 `$STUDIO/projects/<id>/`。外殼的參考程式從 `assets/shells/<風格>/` 複製進去改。

**指令**
```bash
node render.cjs projects/<id> --stills 2,15,40                # 定格 -> stills/t-2.jpg
node render.cjs projects/<id> --preview --from 30 --to 45     # 半解析度預覽一段
RENDER_GPU=1 node render.cjs projects/<id> --from 0 --to 70 --out part1.mp4 --fps 24   # 分段算全片
node render.cjs projects/<id> --poster 120                     # 全片＋海報
```
- `scene.html` 規格：`window.DURATION`、`window.renderAt(t)`（**t 的純函數**：不能用 `Date.now`、CSS transition、`requestAnimationFrame` 累積狀態、不帶種子的亂數）、`window.studioReady`（字型和資料都載完才 resolve）。
- three.js：importmap 指到 `/node_modules/three/build/three.module.js`；`WebGLRenderer({ preserveDrawingBuffer: true })`；WebGL 場景一律加 `RENDER_GPU=1`。
- 字型在 `/node_modules/@fontsource/`（思源黑體、霞鶩文楷、芫荽圓體、Inter）；`studioReady` 前 `await document.fonts.ready`，並 `document.fonts.load` 用到的字。預載的字串要涵蓋片上實際出現的文字（介面字一起算），換語言時才不會落到備用字型。
- 共用小工具 `lib/stage.js`（`rng`、`ease`、`prog`……）用 `import * as S from '/lib/stage.js'`；外殼參考程式會用到。它是工作區（studio）的一部分，雲端算圖會一起複製，所以「場景只讀專案資料夾、`node_modules` 和 `/lib/`」都可以；其他專案外的路徑不行。
- **不要依賴系統字型**：雲端算圖的機器字型不一樣。筆記的 SVG 裡有中文時，先在本機用專案的字型轉成 PNG 放進專案，再當貼圖用。
- `--stills 14.0` 存出來的檔名是 `t-14.jpg`（小數點後的 0 會被吃掉），批次改名時注意。
- 要支援遮掉字的定格：場景讀網址參數（例 `?notext=1`）把字層隱藏，用 `--scene "scene.html?notext=1"` 算。
- 聲音：把整支片的混音（配樂＋音效，48kHz 立體聲，長度＝片長）存成專案裡的 `narration.wav`（檔名沿用工具規格），`render.cjs` 會自動混進影片。
- `--width 1280`：草稿大小輸出（版面仍照 1920×1080 排），短版用；3D 場景只快約 2 成。
- 全片同時最多 2 支，自動排隊。**背景工作超過 2 小時會被砍**：全片分段算（每段 60～80 分鐘內），再用 ffmpeg concat 接起來。

**雲端分段算（建議）**：一支片開一個雲端 session，把全片切成約 8 段平行算，每段算完自己 push；本機只算定格和預覽。工具：`scripts/plan_parts.py`（切段）、`scripts/farm.sh`（在雲端跑）、`scripts/join_parts.sh`（接起來、加聲音），步驟見 `templates/雲端算圖session.md`。一個雲端 session 同時只算 4 段、約 225 秒的片，所以**依片長開 1～4 個 session**（短通常 1、中 2、長 3；`plan_parts.py <秒數> --sessions auto --out-prefix …` 一次產出每個 session 的清單），牆鐘時間約 40～70 分，不隨片長變長（第三輪實測）。所以 `scene.html` 只能讀專案資料夾裡的檔案和 `node_modules`，任意一段都要能單獨算。

**加速（不改畫面）**：3D 算 1600×900 再放大、字維持 DOM 全解析度；只看得到一個房間時其他房間不畫；全黑的格子不畫 3D；陰影只在光源或焦點改變時重算；關掉 MSAA；24fps。目標每格 1 秒內。

**看動態**：`ffmpeg -v error -y -i preview.mp4 -vf "fps=1,scale=480:-1,tile=4x3" sheet_%02d.jpg`，再看圖。審定格一定看全解析度單張。

## 3.5 共用工具（不要每支片重寫）

第三輪三個製作者各自寫了閱讀時間檢查、定格腳本、cue sheet、混音，等於做了三次。現在統一：
1. **`film.json` 是片上的字和段落的唯一資料檔**（`templates/film.json`）：段落（種類：intro／overview／topic／recall／reveal／closure／transition／quiz／ending）和每段字（用途：context／question／rule／recall／reveal／label／quote／card／code／texture）。場景從它讀字，工具也從它讀。
2. `python3 scripts/onscreen.py film.json --cues cues.json --style <風格> --film-id <id> [--lang <影片語言>]`：產生 `onscreen.txt`（給字的檢驗）、印出閱讀時間表（同一套算法，讀不完就 exit 1）、產生配樂 cue sheet。語言沒帶就看 `film.json` 的 `lang`，再沒有就是繁體中文。交第一階段前先跑到全過。
3. `python3 scripts/keystills.py --studio $STUDIO --project projects/<id> --times ... --style <風格> [--gpu]`：關鍵定格有字、遮字兩份（`k01.jpg`…，純編號），`index.json`（只給主持人），`compare.jpg`（和參考圖並排）。
4. 配樂：`scripts/music/pick_music.py --cues cues.json --render <資料夾>` 產生 `score.wav`；`python3 scripts/mix.py --score score.wav --duration <片長> --sfx sfx.json --ending-from <秒> --out narration.wav`。

## 4. 檢查（交付前）

- `ffprobe` 看長度、解析度、有沒有聲音。
- 每 6 秒抽一格拼成接觸表，看全片有沒有黑格、跳格、字被切。
- 響度：`ffmpeg -i final.mp4 -vn -af ebur128=peak=true -f null -`（不要加 `-v error`，否則看不到結果）。
- 分段接起來的地方逐一看接縫。
- 每個數字和片上的字再對一次 `CONTENT.md`。

## 5. 交付

```bash
python3 .claude/skills/engram-quest-episodic-review/scripts/deliver.py \
  --final $STUDIO/projects/<id>/final.mp4 --poster $STUDIO/projects/<id>/poster.jpg \
  --id <id> --title "<片名>" --style episodic-<風格> --vault . \
  --period 2026-10 --length medium [--topics-json topics.json] [--not-taken "主題A,主題B"] [--request-id <插件的要求 id>]
```
- `--period`、`--length` 必填：插件的「情境回顧」分頁依期間分組、顯示片長標籤。`--topics-json` 是章節（`[{"title","from","to"}]`，秒；可從 `film.json` 的主題段匯出），`--not-taken` 是沒選的主題（下一支的候選）。
- 壓成 vault 用的版本（CRF 26、上限 1800 kbps；10 分鐘約 60～100MB），放 `engram-quest/videos/episodic-recall/<id>.mp4`、`<id>.jpg`，更新同資料夾的 `meta.json`（同 id 會取代）。
- GitHub 拒收 100MB 以上的檔：壓出來超過 `--max-mb`（預設 95）時，`deliver.py` 會自動改用兩段式壓縮，壓到約 87MB（第三輪 8 月：軟木牆的紋理讓 CRF 版本到 105MB）。
- **未填標記會擋下交付**：外殼或範本可以用 `{{FILL:某個鍵}}` 標出等待填入的內容，鍵是那段內容的名字。專案裡還留著這種標記時，`deliver.py` 會列出檔名和鍵並停止（exit 2），什麼都不寫進影片庫。只看場景會讀的檔案類型（程式、網頁、資料檔）；`.md`、`tools/` 和註解不算。沒有這種標記就照常交付，所以自己設計外觀的片不受影響。專案不在 `--final` 所在的資料夾時用 `--project` 指定；該資料夾沒有 `scene.html` 時會印出沒檢查的提示，照常交付。
- 製作檔（CONTENT、DEMO、STORYBOARD、NOTES、scene.html、程式、sound／配樂設定）存進 vault 的研究資料夾，影片能再做出來就好。
- 配樂用了有授權的曲子時，`meta.json` 的 `credits` 要寫。

## 6. 交付後

- 給使用者看，記下使用者的原話回饋。
- 被推翻的規則改這個 skill 的 reference（舊規則改掉，不並存）；新的錯寫進 `08-經驗與避坑.md`。
- 發現插件或 skill 的錯：先確認，再開 `debug/issue-*.md` ticket 並告訴使用者。
