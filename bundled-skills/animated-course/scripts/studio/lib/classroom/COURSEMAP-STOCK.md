# 課程地圖：股市入門 `coursemap-stock.js`

> 七課股市入門（st-l01-price … st-l05-plan、st-l06-business、st-l07-statements）共用的課程地圖。**第 1～5 課的呼叫不變，畫面逐像素相同**（桌子仍是 5 個零件）；第 6、7 課用 7 個零件的桌子（第 6、7 課新增 `count`，見 §1）。API 形狀照 `coursemap-pstack.js`（`times`、`cam(t)`、`applyCam`、`update(t, cam)`、`shot`），呼叫方式一樣；多了 `texts(cam)`（給 `window.TEXTS` / `readcheck.cjs`）和 `review: 'group'`。
> 依照 `reference/04-skeleton.md` §5、§5b 做的：全景時整張桌子都在畫面裡；看某一課就推到那個零件、其他零件變淡、字和名牌藏起來（畫面邊緣不會有切一半的字）；一次只亮一組；每個零件亮 ≥ 2.5 s（第 1 課第一次看全貌 3.8 s）；問題卡停到讀完（自動算，含卡上的「第 N 課 · 名牌」）。
> 測試頁：`projects/zz-stockmap7-test/scene.html`（黏土教室裡，一條時間軸接：第 1、2、3、4（group）、5 課 ride、第 5 課 chain（5 個零件的舊桌）→ 第 6 課 ride、第 6 課 group、第 7 課 ride、第 7 課 chain（7 個零件的新桌）；`?set=legacy` 只放前面六段、`?segs=l6,l7,...` 自選、`?mod=base` 換成擴充前的舊版對照）；`times.html` 只算時間。

## 桌上有什麼

黏土零件左到右排（第 1～5 課是 5 個零件的桌子；第 6、7 課是 7 個零件的桌子，第 1～5 個零件完全一樣、桌子和名牌放大），各是那一課核心機制的小模型，每個都會真的演一遍（顏色照 SERIES §5，一種顏色只代表一種量）：

| 課 | 名牌 | 演什麼（一輪，速度 1） | 顏色 |
|---|---|---|---|
| 1 | 獲利 × 倍數 | 左邊一疊金色硬幣（EPS），一根木尺上掛「股價」牌，紫色氣球（本益比）用線拉著牌。硬幣一枚一枚掉下來（2 → 7 枚），一條金色橫桿標出「獲利的高度」，股價牌跟著穩穩往上；接著氣球變大 → 牌往上跳、氣球變小 → 牌掉到橫桿附近、再回到原本大小。前面三個小牌「EPS × 本益比」。**4.4 s** | EPS 金 #E0A526、本益比紫 #7C5CD6 |
| 2 | 看懂報價 | 一支黏土手機。螢幕上方是最新成交價（大字，比開盤高就紅、低就綠），左邊成交點一個一個跑出來連成線，右邊一根 K 線跟著長：影線拉到目前的最高、最低，實體在開盤價和目前價之間，跌破開盤時實體是綠的，最後收在開盤之上 → **紅 K**。推近時旁邊標「開／高／低／收」。下面一排灰色量柱。**4.4 s**（3.6 s 收盤） | 漲紅 #E5484D、跌綠 #1F9D55（台股慣例） |

**小字只在推近時出現**：EPS、本益比、開高低收、賣方／買方、外資／投信／自營商／其他、證券戶／交割戶、下單卡、HPC、營收、60／25／6、損益表／資產負債表／現金流量表、資產／負債／權益、資本支出、自由現金流、預期／實際，在全景時畫成字條（看得出「有字」），推近到那個零件才換成真的字（≥ 28 px；第 6、7 課的卡片小字約 28～32 px，其他 35 px 以上）。全景要讀的是**名牌（5 個零件的桌約 42 px、7 個零件的桌約 40 px）**，加上三個本身就是機制一部分的大字：股價牌、T+0/1/2、10 年旗（全景約 26～30 px，推近 70 px 以上）。

同一個零件的三種狀態：**亮**（有顏色、正在演、名牌變黃、底下一圈淡黃光）／**學過的**（有顏色，停在演完的樣子）／**還沒學或別的零件正在亮**（變淡）。推近到這課的零件時，其他零件更淡（0.9）、它們身上的字和名牌藏起來。

全課收尾（`shot: 'chain'`）：一條長木台從桌面升起墊在全部零件下面，名牌前面多出一條跑道，跑道上的箭頭（5 個零件 4 個、7 個零件 6 個）；一塊「股」積木（帶黃光）從第 1 個跑到最後一個，跑到哪個零件，那個零件就從頭演一次、名牌變黃；演過的保持有顏色（微淡），還沒輪到的很淡；最後全部一起亮、停住。

## 1. 用法

```js
import { makeCourseMapStock } from '/lib/classroom/coursemap-stock.js';   // 也可以 import { makeCourseMap } 或 default
const map = await makeCourseMapStock({ lesson: 3, t0: Ls('O07'), question: '外資賣超，我要跟著跑嗎？', camFrom: CAMS.W, camBlend: 1.0 });
scene.add(map.root);

window.renderAt = (t) => {
  const onMap = t >= map.times.start && t < map.times.end;
  map.root.visible = onMap;
  if (onMap) { map.applyCam(cam, t); map.update(t, cam); }    // update 放在設好鏡頭之後（名牌和問題卡要轉向鏡頭、判斷有沒有出框）
  else { /* 你自己的鏡頭 */ }
  renderer.render(scene, cam);
};
window.TEXTS = (t) => [...myOtherTexts(t), ...(map.root.visible ? map.texts(cam) : [])];   // readcheck.cjs
```
匯出：`makeCourseMapStock`（主要）、`makeCourseMap`（別名）、`default`（同上）、`COL`（顏色意義表，新增 `rev` 營收、`cost` 成本、`capex` 資本支出、`expect` 預期／實際）、`PARTS_STOCK`（七個名牌名）、`readNeed(text)`（§5b 的閱讀秒數公式，跟 readcheck 一樣）。

`update(t, cam)`、`cam(t)`、`applyCam(cam, t)` 都是 **t 的純函數**（任何順序、任何時間，同一格畫面一樣；沒有 Date、沒有 Math.random，成交點的抖動用 `S.rng(2330)`）。頁面記得 `RENDER_GPU=1`。字型：元件自己載入 Chiron GoRound TC 700 和 Inter 800。

### 參數 `makeCourseMapStock(o)`

| 參數 | 預設 | 說明 |
|---|---|---|
| `lesson` | 必填 | 這一課，1～7 |
| `count` | 第 1～5 課 `5`；第 6、7 課 `7` | 桌上有幾個零件：`5` 舊桌（第 1～5 課，畫面和擴充前逐像素相同）、`6`、`7` 新桌。不能小於 `lesson`、也不會小於 5。第 1～5 課想用七個零件的桌子就給 `count: 7`；第 6 課想做「六個接成一條」的收尾給 `count: 6, shot: 'chain'`。7 個零件的桌子：零件間距 0.72 → 0.78、名牌 ×1.36（全景約 40 px）、「獲利 × 倍數」名牌去掉 × 兩邊的空格並和隔壁名牌互相讓開一點、預設 `place.scale` 0.62 → 0.56 |
| `t0` | `0` | 地圖段開始的秒數 |
| `shot` | `'ride'` | `'ride'` 開場（全景 → 依序亮 → 推到這課的零件 + 問題卡）／`'chain'` 全課收尾，全部零件接成一條、積木從 1 跑到最後一個／`'finale'` 從這課零件的近景拉回全景／`'overview'` 停在全景。`shot: 'overview', allLit: true` 用在這張桌的最後一課（`lesson === count`，即第 5 課舊桌、第 7 課新桌）時等於 `'chain'` |
| `question` | `''` | 問題卡的字（`ride` 才有）。一行約 12 個中文字以內，要兩行用 `'\n'`。卡上方自動加「第 N 課 · 名牌名」。卡站在這課零件**旁邊**（第 1～3 課在右、第 4～7 課在左，蓋在變淡的鄰居上），尖角指向零件；推近鏡頭自動把零件和整張卡都框進來（第 6、7 課在桌子右端，卡在左邊，不會被切掉） |
| `times` | 自動 | 跟旁白對時間用，**絕對秒數**，見 §3 |
| `stops` | 第 1 課 `[1..count]`（舊桌 `[1,2,3,4,5]`）；第 N 課 `[1..N−1]`（第 6 課 `[1..5]`、第 7 課 `[1..6]`） | `ride` 推近之前，在全景裡依序亮的零件 |
| `review` | `'wide'` | `'wide'`：每個 stop 輪流在全景裡亮（整桌都在畫面裡）。`'group'`：學過的零件**一起亮、一起演**一個視窗（第 4～7 課想縮短時用；第 6、7 課 1～N−1 一起亮 3.6 s）。`'push'`：鏡頭推到每個 stop（慢，每個 stop 至少給 3 s） |
| `camFrom` | 無 | `{pos, look, fov}`（世界座標 `THREE.Vector3`）：從你的鏡頭在 `t0` 開始平滑接進地圖鏡頭 |
| `camBlend` | `1.2` | 這段接進來要幾秒（建議 1.0） |
| `allLit` | `false` | `overview` 時全部都亮（`lesson === count` 時變成 `chain`） |
| `place` | `{x:0.22, y:0, z:-0.8, rotY:0, scale:0.62}` | 地圖桌放哪（預設在黑板前、包老師和芋圓中間；用地圖時不要再放 `C.makeLowTable()`）。縮放不影響畫面上的大小（鏡頭會自己對準），只影響會不會撞到教室裡的人 |
| `table` | `true` | `false`：不要展示桌，零件板直接放在 `place.y` |
| `parts` | `{}` | 改名牌：`{n: {name}}`（n = 1～7）。預設名牌已對過 SERIES / BRIEF，非必要不要改 |

### 回傳

| 名稱 | 說明 |
|---|---|
| `root` | 加到 scene 的 Group |
| `update(t, cam)` | 擺好第 t 秒的所有東西（要傳 `cam`：名牌轉向、出框判斷、推近時的小字） |
| `cam(t)` / `applyCam(cam, t)` | 地圖鏡頭（世界座標 `{pos, look, fov}`）／直接套到 `PerspectiveCamera` |
| `texts(cam)` | `[{id, text, x0, y0, x1, y1}]`：畫面上的名牌（`map-plate-n`）和問題卡（`map-question`，含標籤），頁面像素座標。放進 `window.TEXTS`。只回報完整在框內的名牌；問題卡長到 90% 才算出現 |
| `times` | `ride`：`{ start, overview, stops:[{n, t, end, rate}], push, arrive, colorIn, ask, readQ, end, lit }`；`chain`：`{ start, join:[a,b], flow:[f1..f_count], per?, allOn, end, lit }`（`flow` 長度＝`count`：舊桌 5、新桌 7）。`console.log(JSON.stringify(map.times))` 看實際數字 |
| `cams.overview()`、`cams.part(n)`、`cams.chain()` | 固定鏡頭：全景／零件 n 的近景（這課的零件會包含問題卡）／接成一條後的全景 |
| `partWorld(n)` | 零件 n 在桌上的世界座標（要包老師指它、加特效時用） |
| `itemWorld(n)` | 零件 n 正在動的東西（股價牌／手機螢幕／第一塊積木／下單卡／曲線頭／圓餅／天秤橫桿）的世界座標，取最近一次 `update` 的位置 |
| `parts`、`land`、`duration` | 內部物件／`end − t0` |

## 2. 每一課怎麼呼叫（建議值）

下面的秒數是**預設值**（`t0 = 0`、`camBlend: 1.0`、只給 `question`，見 `times.html`）；實際使用時把 `t0` 換成你那句旁白的開始，或用 `times.parts` / `arrive` 對到字。

### 第 1 課（st-l01-price）：第一次看全貌，五個依序各演一次，再推到零件 1 + 問題卡
```js
makeCourseMapStock({ lesson: 1, t0: Ls('O0x'), question: '股價漲，到底是什麼在漲？', camFrom: CAMS.W, camBlend: 1.0 })
// 對旁白：times: { parts: [Ls('a'), Ls('b'), Ls('c'), Ls('d'), Ls('e')], arrive: Ls('mapbeat') + 0.2 }（每個 stop 間隔 ≥ 3.5 s）
```
| 段 | 秒（相對 t0） | 停多久 | 畫面 |
|---|---|---|---|
| 接進來＋全景 | 0–2.6 | 2.6 s（含 1.0 s 接鏡頭） | 五個都淡著、整桌在畫面裡 |
| 零件 1～5 依序亮 | 2.6 / 6.4 / 10.2 / 14.0 / 17.8 | 各 **3.8 s**（1.33～1.45× 演完一輪再停） | 全景，一次只有一個有顏色、名牌變黃 |

| **合計** | | **28.5 s** | 想縮短：給 `times.parts` 讓每個 stop 3.2 s，約 25 s |

## 3. 對時間（`times`，全部是絕對秒數）

`ride`（第 6、7 課同；複習的視窗多幾個零件而已）：
| 鍵 | 預設 | 說明 |
|---|---|---|
| `overview` | `t0` | 全景開始 |
| `parts`（或 `stops`） | 自動排 | 每個 stop 亮起的秒數，跟 `stops` 一一對應（`review: 'group'` 時只要一個）。給了 `arrive` 沒給 `parts`：平均排在「全景停完」和「開始推近」之間。沒給：全景停 2.6 s（第 1 課）/ 1.8 s 後，每個 stop 3.8 s（第 1 課）/ 2.7 s（複習；group 一次 3.6 s） |
| `arrive` | 最後一個 stop 結束 + 1.1 s | 鏡頭推到這課零件停好的秒數；問題卡預設這時出現 |
| `push` | `arrive − 1.1` | 開始推近的秒數；最後一個 stop 亮到這裡。推近開始 0.55 s 後，其他零件的字和名牌藏起來 |
| `colorIn`（或 `play`） | 第 1 課 `push + 0.15`；其他 `arrive − 0.6` | 這課零件上色、從頭開演 |
| `rate` | `1` | 這課零件演的速度 |
| `ask` | `arrive` | 問題卡跳出來 |
| `end` | `max(ask + max(2.8, 讀完問題卡 + 0.4), colorIn + 一輪 + 0.4)` | 地圖段結束；鏡頭在 `end − 0.5` 之後不再動。**自己給 `end` 時，`end − ask` 不要小於 `times.readQ`**（否則 readcheck 會報問題卡太短） |

- 每個 stop 從亮起到下一個 stop（或 `push`）是它的視窗。演的速度自動算：`rate = clamp(一輪 / (視窗 − 0.5), 1, 上限)`，上限第 1 課 1.8、複習 2.0。**每個 stop 的視窗請給 ≥ 2.5 s**；第一次看全貌（第 1 課）建議 ≥ 3.5 s。
- 學過的零件在自己的 stop 之前停在「演完的樣子」，亮起時從頭演；沒學過的停在起始樣子。

`chain`：
| 鍵 | 預設 | 說明 |
|---|---|---|
| `join` | `t0 + 0.5 + camBlend × 0.5` | 長木台開始升起（1.4 s 升好，箭頭依序跳出來） |
| `flow` | 自動 | `[f1, …, f_count]`（5 個零件的桌 5 個、7 個零件的桌 7 個）：積木跑到第 n 個零件、它開演的秒數。每段的速度由到下一段的間隔自動算（1～2×） |
| `end` | `allOn + 3.4` | 結束。只給 `end` 不給 `flow`：`count` 段平均分（舊桌每段 2.4～4.5 s、新桌 3.5～4.5 s），最後留 3 s 全亮 |

## 5. 交接與鏡頭

- 從教室接進來：`camFrom` + `camBlend`（建議 1.0 s）。接回你的鏡頭：在 `times.end` 之後自己 lerp。
- 交接到 DOM 頁：鏡頭在 `end − 0.5` 停住；最後一格用 `RENDER_GPU=1 node render.cjs <project> --scene classroom.html --stills <end>` 出圖當貼圖。
- 推近時，這課零件的名牌讓位給問題卡；問題卡是完整的 billboard（正對鏡頭，不會斜）。底部 140 px 沒有東西。
- 全景鏡頭由桌寬決定（5 個或 7 個橫排），畫面上下會有一段黑板托盤和地板；這是讓整張桌子入鏡的代價。7 個零件時桌子更扁：零件在畫面上比 5 個零件的桌小約 28%（零件約 160～200 px 高），所以名牌放大了，全景要讀的只有名牌；細節要推近。

## 6. 算圖成本

1920×1080、SwiftShader、教室＋地圖：每格約 3～4 s，第一格再加約 5 s（字型、canvas 貼圖、shader）。手機螢幕是每格重畫的 canvas（只在畫面內容變了才重畫）。地圖不在畫面上時設 `map.root.visible = false`。`readcheck.cjs` 對整段 135 s 的測試頁約 1 分鐘（新測試頁 211 s 約 45 s）。7 個零件的桌子每格再多約 0.3 s。

## 7. 已知限制

- 預設位置在黑板前；包老師站在 x = −2.25，推近第 1 個零件時畫面最左邊可能露出包老師身體的一角（不擋零件）。要完全避開就在地圖段把老師往左移，或 `place: { x: 0.35 }`。
- 第 2 個零件的價格是示意（開 50、高 58、低 46、收 55），不是真實行情；真行情放在正課畫面。
- 第 5 個零件的兩次下凹是示意形狀（約 −30%、−22%），不是某一段真實歷史。
- 名牌只繞垂直軸轉向鏡頭。
- 沒有音效：要的話在每個 stop 亮起、`times.ask`、chain 的每個 `flow` 加一個小「pop」，第 4 個零件在 T+2（一輪的 2.55 s）加「tick」。
- 第 6 個零件的產品別比例（46／27／17／10%）和三條長條的 60／25／6 都是示意，不是某家公司的數字，圖上只標「HPC」和「60／25／6」，真數字放在正課畫面。第三條只剩 6%（約 1.7 cm 的一小截金色），全景裡只看得到一小塊金色，推近才清楚。
- 第 7 個零件的瀑布、積木、現金流只是形狀示意（沒有刻度、沒有數字）；天秤只表達「實際比預期大一點 → 往實際傾」，大小比例不代表真實 EPS 差距。「預期」虛線方塊在全景裡是 24 個小段，遠看像一個淡紫色的框。
- 7 個零件的桌子：名牌 ×1.36（約 40 px，5 個零件的桌約 42 px）；「獲利 × 倍數」名牌在這張桌上去掉 × 兩邊空格、並和零件 2 的名牌各往兩邊讓 3.5／2 cm，不然會碰在一起。名稱太長（`parts` 改名）或加長時要看全景有沒有互相壓到。
- 第 1～5 課用 `count: 7` 呼叫是支援的，但畫面和舊桌不同（桌寬、名牌大小）；已發布的第 1～5 課請維持預設（`count` 5）。
- `readcheck.cjs` 對同一個 id＋文字只判斷第一次出現（跨段不重算）：要檢查第 6、7 課各段，請對每一段單獨給 `--from/--to`（開始前留 0.5 s 空白，例如 `--from <t0−0.5> --to <end+0.2>`）。
- 零件 6、7 的小字（HPC、60／25／6、卡片上的字）是面向前的字面（跟零件 1～5 的小字一樣）；右前方的卡片會稍微遮住天秤的名牌下緣，已把名牌墊高。
- API 只會長大：已公開的參數和回傳不改（這次只新增 `count`、`lesson` 6～7、`COL` 的四個鍵、`PARTS_STOCK` 的兩項）。
